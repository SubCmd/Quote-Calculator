# UI 규칙

Next.js App Router + TypeScript.

## 금액 취급

- **컴포넌트는 금액을 계산하지 않는다.** 서버가 준 값을 표시만 한다.
  합계를 만들기 위한 `reduce`, `*`, `+` 를 컴포넌트에 쓰지 않는다.
- 금액 표시는 공용 포맷터(`formatKRW`)를 사용한다. 컴포넌트마다 `toLocaleString`을 쓰지 않는다.
- 총액만 보여주지 않는다. 선택 항목별 금액 → 소계 → 할인 → 총액 분해를 항상 노출한다.
- 선택이 없어서 총액이 0원인 것은 오류가 아니다. 0원을 그대로 보여준다. (ADR-0008)
- 표시 금액은 현금가다. 총액 옆에 `현금가`를 명시한다. (ADR-0039)
- **공급가액·세액을 적지 않는다.** 화면·견적서·인쇄본 어디에도 없다.
- 카드 결제 금액은 `payment-amount.ts` 의 함수 결과를 포맷만 해서 쓴다. 컴포넌트에서 `× 1.1` 을
  직접 계산하지 않는다. 적는 자리는 **결제 방식을 고르는 곳 하나**이고, 요약·견적서의 큰 숫자는
  현금가다. 둘 다 큰 글씨로 올리면 어느 쪽이 자기 금액인지 읽히지 않는다.

## 고객 화면 호칭 (ADR-0040)

- 고객이 보는 화면(`/`·`/q/[publicId]`·`/q/[publicId]/print`·탭 제목·개인정보 동의문)에서는
  **`견적` 을 쓰지 않고 `컨쇼 플랜` 으로 적는다.**

| 기존 | 바뀜 |
| ---- | ---- |
| 견적 계산기 | 나만의 컨쇼 플랜 찾기 |
| 견적 요약 | 맞춤형 플랜 요약 |
| 견적서 | 컨쇼 플랜 |
| 견적번호 | 플랜 번호 |
| 견적 요청 | 플랜 요청 |

- **관리자 화면 문구는 `견적` 그대로다.** 코드·DB·감사 로그와 같은 말을 쓰는 쪽이 장애 대응에서 빠르다.
- `/q/` 주소·`publicId`·`Quote` 모델명·컬럼명·`AuditAction` 값·코드 식별자·주석을 바꾸지 않는다.
  주소를 바꾸면 이미 고객에게 나간 링크가 전부 끊긴다.
- 동의문은 **호칭만** 맞춘다. 수집 항목·보유 기간·목적의 내용은 건드리지 않는다.

## 설명 문구 (ADR-0025)

- 단계와 옵션의 `summary` 는 **항상 화면에 있다.** 이름 바로 아래 한 줄로 둔다.
  접어 두기만 하면 고를지 망설이는 순간에 보이지 않아서 없는 것과 같다.
- 긴 설명(`detail`)은 `<details>` 로 접는다. 자체 열림 상태를 컴포넌트에 두지 않는다.
- 펼치기 토글(`자세히`)에는 **눌리는 자리임을 알리는 화살표**를 둔다. 글자만 두면 그냥
  적힌 문구로 읽혀서 누를 수 있다는 것이 전달되지 않는다. 화살표는 CSS `::after` 이고
  접힌 상태에서 오른쪽, 열린 상태에서 아래를 가리킨다.
  **화살표 문자를 `<summary>` 안에 텍스트로 넣지 않는다.** 그 글자가 접근성 이름이 되므로
  스크린 리더가 `자세히 ▸` 를 읽는다. 열림 상태는 `<details>` 가 이미 알린다.
  기본 마커(`list-style`·`::-webkit-details-marker`)는 끈다. 안 끄면 화살표가 둘이 된다.
- **호버 툴팁을 유일한 설명 경로로 두지 않는다.** 터치 기기에는 hover 상태가 없어서
  그 사용자에게는 설명이 존재하지 않게 된다. 첫 탭을 호버로 해석하는 브라우저에서는
  옵션을 고르려던 탭이 설명을 띄우는 데 쓰인다.
- 설명을 **옵션의 `label` 안에 넣지 않는다.** 라벨 영역을 누르면 옵션이 토글되므로,
  설명을 읽으려 누른 동작이 선택을 바꾼다. `label` 바깥 형제 요소로 둔다.
- 설명은 관리자가 입력한 문자열이다. **HTML·마크다운으로 해석하지 않는다.**
  `dangerouslySetInnerHTML` 을 쓰지 않고, 줄바꿈만 `white-space: pre-line` 으로 살린다.
- 설명이 없는 단계·옵션이 정상이다. 빈 자리에 `설명 없음` 같은 문구를 채우지 않는다.
- 견적 상세·인쇄 화면에는 설명을 넣지 않는다. 설명은 스냅샷이 아니라 현재 문구라서
  과거 견적에 붙이면 그 고객이 본 내용과 달라진다.

## 묶음 안내 (ADR-0037)

- 안내는 **견적 요약 안**에 둔다. 총액 바로 아래 항상 보이는 자리다. 접지 않는다.
  금액 이야기라서 옵션 목록 옆이 아니다. 옵션 줄 옆에 누르는 자리를 만들면 옵션을
  고르려던 탭이 선택을 통째로 바꾼다.
- **바꾸기는 버튼이다. 입력이 아니다.** 체크박스·토글로 두지 않는다. 상태를 가지면
  다른 입력에 뒤집히고, 고객이 자기가 무엇을 고른 상태인지 못 읽는다. (ADR-0026의 전체 선택)
- 버튼은 서버가 준 `nextOptionIds` 를 **그대로** 선택 상태에 넣는다. 무엇을 빼고 더할지
  컴포넌트가 계산하지 않는다. 조립하면 안내한 절약액과 실제 결과가 어긋날 수 있다.
- 절약액도 서버 값을 포맷만 해서 쓴다. 금액끼리 빼지 않는다.
- 안내가 없는 선택이 정상이다. 빈 자리에 `묶음 없음` 같은 문구를 채우지 않는다.
- **자동으로 바꾸지 않는다.** 고객이 누르지 않았는데 체크가 움직이면 안 된다.
- 묶음 옵션은 안내와 별개로 옵션 목록에 그대로 있다. 안내 전용으로 숨기지 않는다.

## 컴포넌트 구분

- 기본은 Server Component. 상호작용이 필요한 부분만 `'use client'`를 붙인다.
- `'use client'` 범위를 화면 단위가 아니라 위젯 단위로 좁게 잡는다.
- Server Component에서 Repository나 Prisma를 직접 호출하지 않는다. Service를 거친다.

## 데이터 호출

- 금액 계산은 `POST /api/estimate`로 요청한다.
- 선택이 바뀔 때마다 호출하되 디바운스(300ms 기준)를 적용하고, 이전 요청은 `AbortController`로 취소한다.
- 응답이 도착하는 순서를 신뢰하지 않는다. 마지막 요청의 응답만 화면에 반영한다.
- 계산 중에는 **이전 금액을 그대로 두지 말고** 계산 중 상태를 표시한다. 낡은 금액이 확정값처럼 보이면 안 된다.

## 상태

- 서버에서 온 값(가격, 옵션 목록)을 클라이언트 상태에 복제해 두고 가공하지 않는다.
- 폼 상태는 선택값(`productId`, `optionIds`)만 보유한다. 금액은 서버 응답을 그대로 쓴다.
- 상품은 탭(`role="tablist"`)으로 고른다. 탭을 바꾸면 `optionIds`를 비운다. 상품이 다르면 옵션도 다르다.
- **이미 선택된 옵션을 다시 누르면 해제된다.** 단일 선택 그룹도 마찬가지다.
  라디오는 기본 동작으로 해제가 안 되므로 `change`가 아니라 `click`을 받는다.
  고르지 않은 그룹은 금액에 들어가지 않을 뿐, 그 자체가 위반은 아니다.
- 선행 그룹(`dependsOnGroupId`)이 충족되지 않은 그룹은 입력을 `disabled`로 두고 사유를 적는다.
  선행 선택이 풀리면 거기 딸린 선택도 함께 지운다. 연쇄도 끝까지 정리한다. (ADR-0010)
  - 선행이 **옵션 하나**로 좁혀진 그룹은 사유에 **그 옵션 이름**을 적는다. (ADR-0044)
    `먼저 '6단계 (60~80분)' 을 선택해 주세요` 다. 그룹 이름만 적으면 고객이 어느 단계인지
    찾으려고 목록 전체를 다시 훑는다. 이름은 서버가 준 값이고 화면이 만들지 않는다.
  - 선행 옵션이 **해석되지 않은** 그룹(코드는 있는데 그 옵션이 없는 경우)은 잠근 채로 두고
    `지금은 선택할 수 없는 항목입니다` 만 적는다. 옵션 코드를 화면에 노출하지 않는다. (ADR-0021)
  - **미충족 그룹을 숨기지 않는다.** 숨기면 그 상담이 존재하는지도 모른다.
- **안내 전용 단계(`noticeOnly`)는 입력 없이 그린다.** (ADR-0048) 고를 것이 없는 단계다.
  `fieldset` · `legend` 가 아니라 `section` 이고, 단계 번호 · 이름 · 설명만 둔다.
  필수·선택 표시를 붙이지 않는다. 0원 옵션이나 `disabled` 체크박스로 흉내 내지 않는다.
  체크박스가 보이면 고객은 고를 것으로 읽고, 고르지 않은 채 진행하면 그 단계를 건너뛴
  것으로 오해한다. 실제로는 반드시 제공되는 단계다.
  **그래도 자리는 남긴다.** 숨기면 그 단계가 있는지 모른다. (위 미충족 그룹과 같은 선)
  고를 수 있는 단계처럼 보이지 않게 흐린 모양으로 둔다.
  선행 그룹이 충족되지 않았으면 잠긴 모양과 사유를 그대로 적는다. (ADR-0010)
- **전체 선택·통합 체크 같은 보조 입력을 만들지 않는다.** (ADR-0026) 입력 하나가 다른 입력을
  여러 개 바꾸면 고객이 자기가 무엇을 고른 상태인지 읽지 못한다. 옵션 하나를 끄면 체크가
  저절로 풀려서, 건드리지 않은 입력이 움직인 것으로 보인다.
  묶음으로 파는 상담은 화면 보조 입력이 아니라 **옵션 하나**로 등록한다.
- 금지된 것은 **상태를 가진 입력**이다. **버튼은 둘 수 있다.** (ADR-0043)
  `모두 선택` 은 `<button type="button">` 이고 눌린 모양도 켜진 모양도 없다.
  `aria-pressed` 를 붙이지 않는다. 선택은 체크박스에만 있다.
  - **전부 켜져 있지 않으면 전부 켜고, 전부 켜져 있으면 전부 끈다.** 한 번 더 누르면
    방금 켠 것이 취소된다. 일부만 켜져 있을 때는 끄지 않고 나머지를 채운다.
  - 해제도 `pruneUnmetGroups` 를 거친다. 선행이 풀린 그룹의 선택이 함께 지워진다. (ADR-0010)
  - `모두 해제` 를 **별도 버튼으로 나란히 두지 않는다.** 전부 켜진 상태에서 누를 수 있는데
    아무 일도 하지 않는 버튼이 남는다.
  - 버튼을 둘 그룹은 `OptionGroup.selectAll` 이 정한다. **상품 코드로 분기하지 않고**,
    모든 다중 선택 그룹에 자동으로 붙이지도 않는다. 묶음 옵션이 같은 그룹에 있으면
    전부 켰을 때 같은 상담을 두 번 사게 된다. (ADR-0026, ADR-0037)
  - 라벨은 자기 상태가 아니라 **지금 누르면 일어날 일**이다. `{group.name} 모두 선택` /
    `{group.name} 모두 해제` 로 **값에서 만든다.** `1~6단계` 처럼 개수를 손으로 적으면
    옵션이 하나 늘었을 때 거짓이 된다.
  - 라벨과 동작의 판정은 `src/lib/select-all.ts` 의 순수 함수 하나다. 화면이 `every` 를
    직접 적지 않는다. 같은 판정을 써야 버튼 글자와 누른 결과가 어긋나지 않는다.
  - 선행 그룹이 잠긴 그룹에서는 버튼도 잠긴다. 개별 체크박스로 할 수 없는 일을
    버튼으로 할 수 있게 두지 않는다. (ADR-0010)
- 옵션·단계·상품은 서버가 준 순서(`sortOrder` 정렬 결과)대로 그린다. 화면에서 다시 정렬하지 않는다.
- URL로 공유·복원이 필요한 선택값은 쿼리 파라미터에 둔다.
  **개인정보는 선택값이 아니다.** 이름·휴대전화번호는 공유·복원 대상이 아니므로 쿼리
  파라미터에 두지 않는다. 방문 기록·서버 접근 로그·바깥 링크의 `Referer` 에 남는다. (ADR-0045)

## 플랜 조회 (ADR-0045)

- `/q/lookup` 은 이름과 휴대전화번호를 **둘 다** 받는다. 한 칸만으로 조회하는 길을 두지 않는다.
- 요청은 `POST` 이고 결과는 **화면 상태로만** 들고 있다. 조회 조건도 결과도 URL 에 없다.
- **찾지 못했을 때의 문구는 하나다.** 이름이 틀렸는지 번호가 틀렸는지 애초에 없는지를
  나눠 적지 않는다. 나눠 적으면 `이름은 맞다` 가 응답으로 새어 나간다.
- 결과에 입력한 이름·전화번호를 **되돌려 적지 않는다.** 맞혔다는 사실만 확인시켜 준다.
  고른 옵션·할인 내역도 적지 않는다. 자세한 내역은 `/q/{publicId}` 링크로 간다.
- 상태 문구는 서버가 준 값이다. 화면이 `REQUESTED` 같은 코드로 분기하는 표를 들고 있지 않는다.
- **조회 화면에 쓰기 동작을 두지 않는다.** 결제 방식 선택은 `/q/{publicId}` 에 있다. (ADR-0033)
  목록에 쓰기를 두면 한 번의 오조회가 남의 플랜 상태를 건드린다.
- 잠금 응답(`429`)의 본문 문구는 그대로 적는다. 남은 시도 횟수는 서버가 보내지 않는다.
  500 의 본문은 읽지 않고 **상태 코드만 보고** 고정 문구를 띄운다. (ADR-0021)
- 조회 화면으로 가는 길을 둔다. 첫 화면 머리말과 `/q/{publicId}` 하단이다.
  주소를 보관하지 못한 고객이 찾아올 자리가 없으면 화면을 만든 뜻이 없다.

## 동의와 약관 (ADR-0042)

- 동의는 **개인정보 수집·이용**과 **취소·환불 규정** 둘이다. 둘 다 `[필수]` 이고 둘 다
  체크해야 요청 버튼이 열린다. 하나의 체크박스로 묶지 않는다. 근거 법이 다르고,
  체크박스 라벨이 동의 내용을 말해야 증명이 된다.
- 각 동의 블록은 **항상 보이는 요약**을 갖는다. 접지 않는다. 전문은 `/privacy` · `/refund`
  전용 페이지이고 요약 밑에 `전문 보기` 링크를 둔다. 8개 조항을 요청 폼 안에 펼치면
  이름·휴대폰 입력란이 스크롤 아래로 밀리고, 접으면 고지가 접힌 채 동의를 받는 셈이다.
- 전문 링크는 **새 탭**이다 (`target="_blank" rel="noopener noreferrer"`). 요청 폼의 선택은
  `useState` 에 있고 URL 에 없어서, 같은 탭에서 이동하면 돌아왔을 때 고른 것이 전부 사라진다.
  규정을 읽으러 간 행동이 선택을 지워서는 안 된다. (ADR-0025 가 설명을 `label` 밖에 둔 것과 같은 선)
- **요약과 전문이 어긋나지 않게 한다.** 전문을 고치면 요청 폼의 요약 배열도 같이 본다.
- 약관 내용을 DB 로 옮기지 않는다. 바뀌면 배포하고 버전 관리는 git 이 한다.
- 보내지 않는 것을 목적으로 적지 않는다. 발송 수단이 없는 이메일 선택 동의 블록을 만들면
  고지가 거짓이 된다. (ADR-0018 의 배경)

## 검증

- 클라이언트 검증은 UX 보조다. 서버 검증을 생략하는 근거가 되지 않는다.
- 옵션 제약 위반 응답(`violations`)은 해당 옵션 그룹 옆에 사유를 표시한다. 전체 화면 에러로 처리하지 않는다.

## 예외 표시 (ADR-0021)

- **예외 메시지(`error.message`)를 화면에 렌더링하지 않는다.** 옵션·할인 코드가 그대로 들어 있고,
  `/q/[publicId]` 는 인증 없는 공개 경로다. 보여주는 것은 `error.digest` 하나뿐이다.
- 500 응답의 본문을 읽어 화면에 옮기지 않는다. **상태 코드만 보고** 고정 문구를 띄운다.
- **계산이 실패하면 금액 자리를 비워 두지 않는다.** 아무 말도 없는 빈 요약은 0원으로 읽힌다.
  사유를 띄우고 견적 요청 버튼은 열지 않는다.
- 계산 실패를 `violations` 에 섞지 않는다. 위반은 고객이 선택을 바꿔 풀 수 있고, 실패는 아니다.
- `error.tsx` 는 **렌더링 예외만** 받는다. `fetch` 안에서 터진 것은 호출한 쪽이 직접 다뤄야 한다.

## 접근성·표기

- 모든 입력에 `label`을 연결한다.
- 금액 변경은 `aria-live`로 알린다.
- 금액 숫자는 `tabular-nums`로 자리를 고정한다.

## 금지

- 컴포넌트에 옵션 금액·할인율 하드코딩.
- 상품 코드나 옵션 코드로 화면을 분기하기. 그룹의 `singleSelect` 같은 메타데이터로 그린다.
- 가격 규칙 전체를 클라이언트로 내려보내기.
- 계산 결과를 `localStorage`에 저장해 재사용하기. (규칙이 바뀌면 낡은 금액이 된다)
