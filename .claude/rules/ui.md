# UI 규칙

Next.js App Router + TypeScript.

## 금액 취급

- **컴포넌트는 금액을 계산하지 않는다.** 서버가 준 값을 표시만 한다.
  합계를 만들기 위한 `reduce`, `*`, `+` 를 컴포넌트에 쓰지 않는다.
- 금액 표시는 공용 포맷터(`formatKRW`)를 사용한다. 컴포넌트마다 `toLocaleString`을 쓰지 않는다.
- 총액만 보여주지 않는다. 선택 항목별 금액 → 소계 → 할인 → 총액 분해를 항상 노출한다.
- 선택이 없어서 총액이 0원인 것은 오류가 아니다. 0원을 그대로 보여준다. (ADR-0008)
- 모든 금액은 부가세 포함이다. 총액 옆에 `부가세 포함`을 명시한다. (ADR-0005)
- 공급가액·세액 분리 표기가 필요하면 `tax.ts` 역산 함수 결과를 쓴다. 컴포넌트에서 `/1.1` 을 직접 계산하지 않는다.

## 설명 문구 (ADR-0025)

- 단계와 옵션의 `summary` 는 **항상 화면에 있다.** 이름 바로 아래 한 줄로 둔다.
  접어 두기만 하면 고를지 망설이는 순간에 보이지 않아서 없는 것과 같다.
- 긴 설명(`detail`)은 `<details>` 로 접는다. 자체 열림 상태를 컴포넌트에 두지 않는다.
- 펼치기 토글(`자세히`)에는 **눌리는 자리임을 알리는 화살표**를 둔다. 글자만 두면 그냥
  적힌 문구로 읽혀서 누를 수 있다는 것이 전달되지 않는다. 화살표는 CSS `::after` 이고
  접힌 상태에서 오른쪽, 열린 상태에서 아래를 가리킨다.
  **화살표 문자를 `<summary>` 안에 텍스트로 넣지 않는다.** 그 글자가 접근성 이름이 되므로
  스크린 리더가 `자세히 ▸` 를 읽는다. 열림 상태는 `<details>` 가 이미 알린다.
  기본 마커(`list-style`·`::-webkit-details-marker`)는 끈다. 안 끄면 화살표가 둘이 된다.
- **호버 툴팁을 유일한 설명 경로로 두지 않는다.** 터치 기기에는 hover 상태가 없어서
  그 사용자에게는 설명이 존재하지 않게 된다. 첫 탭을 호버로 해석하는 브라우저에서는
  옵션을 고르려던 탭이 설명을 띄우는 데 쓰인다.
- 설명을 **옵션의 `label` 안에 넣지 않는다.** 라벨 영역을 누르면 옵션이 토글되므로,
  설명을 읽으려 누른 동작이 선택을 바꾼다. `label` 바깥 형제 요소로 둔다.
- 설명은 관리자가 입력한 문자열이다. **HTML·마크다운으로 해석하지 않는다.**
  `dangerouslySetInnerHTML` 을 쓰지 않고, 줄바꿈만 `white-space: pre-line` 으로 살린다.
- 설명이 없는 단계·옵션이 정상이다. 빈 자리에 `설명 없음` 같은 문구를 채우지 않는다.
- 견적 상세·인쇄 화면에는 설명을 넣지 않는다. 설명은 스냅샷이 아니라 현재 문구라서
  과거 견적에 붙이면 그 고객이 본 내용과 달라진다.

## 컴포넌트 구분

- 기본은 Server Component. 상호작용이 필요한 부분만 `'use client'`를 붙인다.
- `'use client'` 범위를 화면 단위가 아니라 위젯 단위로 좁게 잡는다.
- Server Component에서 Repository나 Prisma를 직접 호출하지 않는다. Service를 거친다.

## 데이터 호출

- 금액 계산은 `POST /api/estimate`로 요청한다.
- 선택이 바뀔 때마다 호출하되 디바운스(300ms 기준)를 적용하고, 이전 요청은 `AbortController`로 취소한다.
- 응답이 도착하는 순서를 신뢰하지 않는다. 마지막 요청의 응답만 화면에 반영한다.
- 계산 중에는 **이전 금액을 그대로 두지 말고** 계산 중 상태를 표시한다. 낡은 금액이 확정값처럼 보이면 안 된다.

## 상태

- 서버에서 온 값(가격, 옵션 목록)을 클라이언트 상태에 복제해 두고 가공하지 않는다.
- 폼 상태는 선택값(`productId`, `optionIds`)만 보유한다. 금액은 서버 응답을 그대로 쓴다.
- 상품은 탭(`role="tablist"`)으로 고른다. 탭을 바꾸면 `optionIds`를 비운다. 상품이 다르면 옵션도 다르다.
- **이미 선택된 옵션을 다시 누르면 해제된다.** 단일 선택 그룹도 마찬가지다.
  라디오는 기본 동작으로 해제가 안 되므로 `change`가 아니라 `click`을 받는다.
  고르지 않은 그룹은 금액에 들어가지 않을 뿐, 그 자체가 위반은 아니다.
- 선행 그룹(`dependsOnGroupId`)이 충족되지 않은 그룹은 입력을 `disabled`로 두고 사유를 적는다.
  선행 선택이 풀리면 거기 딸린 선택도 함께 지운다. 연쇄도 끝까지 정리한다. (ADR-0010)
- **전체 선택·통합 체크 같은 보조 입력을 만들지 않는다.** (ADR-0026) 입력 하나가 다른 입력을
  여러 개 바꾸면 고객이 자기가 무엇을 고른 상태인지 읽지 못한다. 옵션 하나를 끄면 체크가
  저절로 풀려서, 건드리지 않은 입력이 움직인 것으로 보인다.
  묶음으로 파는 상담은 화면 보조 입력이 아니라 **옵션 하나**로 등록한다.
- 옵션·단계·상품은 서버가 준 순서(`sortOrder` 정렬 결과)대로 그린다. 화면에서 다시 정렬하지 않는다.
- URL로 공유·복원이 필요한 선택값은 쿼리 파라미터에 둔다.

## 검증

- 클라이언트 검증은 UX 보조다. 서버 검증을 생략하는 근거가 되지 않는다.
- 옵션 제약 위반 응답(`violations`)은 해당 옵션 그룹 옆에 사유를 표시한다. 전체 화면 에러로 처리하지 않는다.

## 예외 표시 (ADR-0021)

- **예외 메시지(`error.message`)를 화면에 렌더링하지 않는다.** 옵션·할인 코드가 그대로 들어 있고,
  `/q/[publicId]` 는 인증 없는 공개 경로다. 보여주는 것은 `error.digest` 하나뿐이다.
- 500 응답의 본문을 읽어 화면에 옮기지 않는다. **상태 코드만 보고** 고정 문구를 띄운다.
- **계산이 실패하면 금액 자리를 비워 두지 않는다.** 아무 말도 없는 빈 요약은 0원으로 읽힌다.
  사유를 띄우고 견적 요청 버튼은 열지 않는다.
- 계산 실패를 `violations` 에 섞지 않는다. 위반은 고객이 선택을 바꿔 풀 수 있고, 실패는 아니다.
- `error.tsx` 는 **렌더링 예외만** 받는다. `fetch` 안에서 터진 것은 호출한 쪽이 직접 다뤄야 한다.

## 접근성·표기

- 모든 입력에 `label`을 연결한다.
- 금액 변경은 `aria-live`로 알린다.
- 금액 숫자는 `tabular-nums`로 자리를 고정한다.

## 금지

- 컴포넌트에 옵션 금액·할인율 하드코딩.
- 상품 코드나 옵션 코드로 화면을 분기하기. 그룹의 `singleSelect` 같은 메타데이터로 그린다.
- 가격 규칙 전체를 클라이언트로 내려보내기.
- 계산 결과를 `localStorage`에 저장해 재사용하기. (규칙이 바뀌면 낡은 금액이 된다)
