# ADR-0019. 입금 계좌는 환경변수에서 읽고, 입금받을 수 있는 견적에만 표기한다

- 상태: 수락됨
- 날짜: 2026-10-07
- 관련: ADR-0012, ADR-0016, F-5-1

## 배경

견적을 요청한 고객이 다음에 할 일은 입금이다. 지금은 금액만 보여주고 어디로 보낼지는 말하지 않아서,
고객이 담당자에게 따로 물어봐야 한다. 견적서에도 계좌가 없다.

발행처 정보(상호·사업자번호·대표자·주소·연락처)는 ADR-0016 에서 이미 환경변수로 읽고 있다.
입금 계좌도 같은 성격의 값이다. 가격처럼 자주 바뀌지 않고, 관리자가 화면에서 고칠 일이 없다.

## 결정

**예금주·은행명·계좌번호를 환경변수에서 읽어, 입금받을 수 있는 견적에만 표기한다.**

| 환경변수 | 내용 |
| ---- | ---- |
| `QUOTE_SUPPLIER_BANK_NAME` | 은행명 |
| `QUOTE_SUPPLIER_ACCOUNT_HOLDER` | 예금주 |
| `QUOTE_SUPPLIER_ACCOUNT_NO` | 계좌번호 |

- **세 개가 모두 있을 때만 표기한다.** 하나라도 비면 계좌 영역을 그리지 않는다.
  ADR-0016 의 발행처 항목은 하나씩 독립이라 있는 것만 찍었지만, 계좌는 셋이 한 덩어리다.
  예금주 없는 계좌번호, 은행 없는 계좌번호는 입금에 쓸 수 없다. 반쪽을 보여 주면 고객이 전화해야 한다.
- 표기 위치는 **고객 조회 페이지(`/q/[publicId]`)와 인쇄 견적서(`/q/[publicId]/print`) 둘 다**다.
- **입금받을 수 없는 견적에는 표기하지 않는다.** 표시 상태 기준이다. (ADR-0012)

| 표시 상태 | 계좌 표기 |
| ---- | ---- |
| `DRAFT` / `REQUESTED` / `CONFIRMED` | 표기 |
| `EXPIRED` | 표기하지 않음 |
| `CANCELED` | 표기하지 않음 |

## 이유

- **환경변수를 쓰는 이유는 ADR-0016 과 같다.** 계좌는 가격 규칙이 아니다. 버전 이력도, 적용 시작일도,
  편집 화면도 필요 없다. DB 테이블과 관리자 화면을 만들면 거의 바뀌지 않는 값 하나를 위해
  스키마·Repository·Service·화면이 네 겹 늘어난다.
- **코드에 박지 않는 이유는 계좌가 바뀔 수 있기 때문이다.** 은행을 옮기거나 사업자 명의가 바뀌면
  계좌만 교체하면 된다. 소스 수정·커밋·재배포가 아니라 환경변수 교체다.
  계좌번호가 소스와 git 이력에 남지 않는 것도 덤이다.
- **만료·취소 견적에 계좌를 띄우지 않는 이유가 핵심이다.** 금액이 더 이상 유효하지 않은 견적을 보고
  입금하면 잘못된 돈이 들어온다. 환불은 돈과 신뢰를 함께 깎는다. 입금 유도는 유효한 견적에만 한다.
- **공개 URL 노출은 받아들인다.** `/q/[publicId]` 는 인증이 없어 링크를 아는 누구에게나 보인다.
  하지만 공개되는 값은 **입금받을 쪽의 계좌**다. 명함과 세금계산서에 이미 적는 정보이고,
  계좌번호를 안다고 출금할 수 있는 것이 아니다. 반대로 숨기면 고객이 입금을 못 한다.
- **고객 연락처와는 다르게 다룬다.** 연락처는 ADR-0013 에 따라 이 페이지에 찍지 않는다.
  남의 개인정보와 자기 계좌는 노출 비용이 다르다.

## 하지 않기로 한 것

- **가상계좌·결제 연동.** Q-7 그대로 범위 외다. 계좌 이체 안내만 한다.
- **입금 확인·대조 기능.** 입금 여부는 사람이 통장을 보고 `CONFIRMED` 로 바꾼다.
  자동 대조는 오픈뱅킹 연동이 필요하고 결제 연동과 같은 결정에 묶인다.
- **계좌를 DB 로 옮기고 관리자 화면에서 편집.** 위 "이유" 그대로. 계좌가 여러 개가 되거나
  상품별로 달라지면 그때 다시 결정한다.
- **계좌 여러 개 지원.** 지금 계좌는 하나다. 여러 개를 띄우면 고객이 어디로 보낼지 고민한다.
- **입금 기한 표기.** 견적 유효기간(ADR-0012)과 입금 기한은 다른 개념이고,
  입금 기한 정책이 정해진 적이 없다. 추측해서 적지 않는다.

## 영향

- `src/lib/supplier.ts` 에 `supplierAccount()` 가 생긴다. 셋 중 하나라도 없으면 `null` 을 돌려준다.
  `supplierFields()` 와 달리 부분 결과가 없다.
- `.env.example` 에 세 변수가 추가된다. 운영 배포 시 채워야 하는 값 목록이 늘어난다.
  비워 두면 계좌가 안 보일 뿐 견적 기능은 그대로 동작한다. 금액은 환경변수와 무관하다.
- 환경변수라서 값을 고치면 **서버를 다시 띄워야** 반영된다. 무중단 교체가 아니다.
  계좌가 자주 바뀌는 상황이 오면 이 결정을 다시 본다.
