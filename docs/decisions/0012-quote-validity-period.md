# ADR-0012. 견적 유효기간은 30일이고, 만료는 저장하지 않고 파생한다

- 상태: 수락됨
- 날짜: 2026-10-06
- 관련: Q-4, `docs/architecture.md` 6절

## 배경

가격 규칙은 덮어쓰지 않고 새 버전이 쌓인다(ADR-0002). 그래서 어제 뽑은 견적과
오늘 계산한 금액이 다를 수 있다. 견적에 유효기간이 없으면 반년 전 금액을 들고 와
"이 금액으로 해 달라"는 요구를 거절할 근거가 없다.

`Quote` 모델에는 이미 `expiresAt` 컬럼과 `QuoteStatus.EXPIRED` 가 있지만,
언제 만료되는지와 **누가 만료로 바꾸는지**가 정해져 있지 않았다.

## 결정

**유효기간 기본값은 계산 시점으로부터 30일이다. 만료 여부는 저장하지 않고 조회 시점에 파생한다.**

- 견적을 저장할 때 `expiresAt = calculatedAt + 30일` 을 **값으로 박아 둔다.**
  나중에 정책이 60일로 바뀌어도 이미 발행된 견적의 기한은 움직이지 않는다.
- `QuoteStatus.EXPIRED` 를 **DB 에 쓰지 않는다.** 표시 상태는
  `저장된 status` 와 `expiresAt < now` 를 함께 보고 그때그때 계산한다.
- **`CONFIRMED` 견적은 만료되지 않는다.** 확정은 되돌리지 않는다(`CLAUDE.md` 6번).
- 만료된 견적은 금액을 계속 보여준다. 숨기지 않고 "유효기간이 지났습니다"를 함께 표시한다.

## 이유

- **배치 작업을 만들지 않아도 된다.** 상태를 저장하면 매일 도는 작업이 필요하고,
  그 작업이 멈추면 DB 가 거짓말을 한다. 시각 비교는 틀릴 수 없다.
- **`now` 를 인자로 받는 기존 계산 규약과 같다**(`.claude/rules/pricing.md`).
  만료 판정도 같은 입력 → 같은 출력이라 테스트에서 시각을 고정할 수 있다.
- 30일은 입시 일정 한 사이클(원서·상담 주기) 안에서 결정이 끝나는 길이다.
  너무 짧으면 상담 중에 만료되고, 너무 길면 가격 개정분을 흡수하지 못한다.

## 하지 않기로 한 것

- **만료 배치 작업.** 위 이유대로 필요 없다.
- **`QuoteStatus.EXPIRED` enum 값 삭제.** 표시 상태의 이름으로 계속 쓴다.
  Postgres 에서 enum 값 제거는 깔끔하지 않고(`.claude/rules/database.md`), 지울 이득도 없다.
- **견적별 유효기간 커스텀 입력.** 담당자가 기한을 늘릴 수 있어야 한다는 요구가
  아직 없다. 필요해지면 `expiresAt` 이 이미 컬럼이므로 입력만 붙이면 된다.

## 영향

- `docs/architecture.md` 6절의 상태 전이도에서 `EXPIRED` 는 저장 상태가 아니라고 명시해야 한다.
- 만료된 견적으로 계약을 진행하려면 복제해서 새 견적을 만들어야 한다(재계산된다).
- 유효기간을 바꾸려면 상수 하나(`QUOTE_VALIDITY_DAYS`)만 고치면 되고,
  이미 발행된 견적에는 영향이 없다.
