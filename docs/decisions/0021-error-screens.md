# ADR-0021. 예외 화면은 원인을 말하지 않고, 고객과 관리자에게 다른 문구를 보여준다

- 상태: 수락됨
- 날짜: 2026-10-08
- 관련: ADR-0009, ADR-0011, ADR-0013, `.claude/rules/ui.md`

## 배경

이 프로젝트는 **가격 데이터가 깨지면 일부러 예외를 던진다.** (ADR-0009)
할인 조건이 가리키는 옵션이 없으면 조건을 무시하지 않고 `throw` 한다. 조용히 넘어가면
할인이 과하게 걸려서 **화면 금액과 받을 금액이 달라지기** 때문이다. 이건 끄면 안 되는 설계다.

그런데 던진 예외를 받아 줄 화면이 없었다. `app/` 아래에 `error.tsx` 가 없어서 Next.js 기본 화면이
그대로 떴다. 기본 화면은 영문이고, 개발 모드에서는 **예외 메시지와 스택을 그대로 보여준다.**

던지는 메시지는 이런 모양이다.

```
할인 'EARLY_BIRD' 의 조건 옵션을 찾을 수 없습니다: COMMUNICATION/KAKAO
```

옵션 코드·할인 코드·그룹 코드가 그대로 들어 있다. 고객에게 보여 줄 문장이 아니다.

`notFound()` 도 마찬가지다. 없는 견적 주소(`/q/[publicId]`)를 열면 Next.js 기본 404 가 뜬다.
고객이 보는 경로인데 화면만 영어다.

### 예외가 실제로 어디서 터지는지 확인했다

`error.tsx` 는 **렌더링 중** 예외만 받는다. `fetch` 안에서 터진 것은 받지 않는다.
그래서 서버 렌더링 경로가 실제로 무엇을 읽는지 세어 봤다.

| 경로 | 서버에서 읽는 것 | 가격 규칙 해석(ADR-0009)을 지나는가 |
| ---- | ---- | ---- |
| `/` | 카탈로그 (금액 제외) | 아니오 |
| `/q/[publicId]` | 저장된 스냅샷 | 아니오 (재계산하지 않는다) |
| `/admin` | 관리자용 원본 행 | 아니오 |

**가격 데이터 오류는 서버 렌더링이 아니라 `POST /api/estimate` 에서 터진다.** 즉 `error.tsx` 로
오지 않는다. 운영 빌드로 직접 확인했다. 할인 조건의 옵션 코드를 없는 값으로 바꾸고 옵션을 고르니
화면은 이렇게 됐다.

- 내부 메시지는 새지 않았다. (Route 가 JSON 이 아닌 500 을 주고, 클라이언트 `.catch` 가 받는다)
- **대신 아무 말도 하지 않았다.** 옵션을 골랐는데 금액도, 오류도, 계산 중 표시도 없었다.

조용한 빈 화면은 기본 오류 화면보다 나쁘다. 고객은 **금액이 0원이라고 읽거나, 자기가 덜 골랐다고
생각한다.** 금액이 안 나온 이유를 말하지 않는 것은 이 프로젝트의 제1 원칙(화면 금액 = 지불 금액)을
지키는 방식이 아니다.

그래서 `error.tsx` 가 실제로 받는 것은 **인프라 장애**(DB 연결 끊김 등)다. 가격 데이터 오류는
계산 요청 쪽에서 따로 말해 줘야 한다. 둘 다 필요하다.

## 결정

**예외 화면 세 개를 만들고, 계산 실패는 네 번째 자리에서 말한다. 예외 메시지는 어디에도 쓰지 않는다.**

| 파일 | 받는 것 | 보는 사람 |
| ---- | ---- | ---- |
| `app/error.tsx` | 고객 경로(`/`, `/q/**`)의 렌더링 예외 | 고객 |
| `app/admin/error.tsx` | 관리자 경로의 렌더링 예외 | 담당자 |
| `app/not-found.tsx` | `notFound()` 와 없는 주소 | 양쪽 |
| `app/quote-form.tsx` 의 견적 요약 | `/api/estimate` 의 500·네트워크 실패 | 고객 |

- **`error.message` 를 화면에 렌더링하지 않는다.** 대신 Next.js 가 주는 `error.digest` 만 보여준다.
  `digest` 는 서버 로그의 같은 항목을 가리키는 불투명한 해시다.
- **고객에게는 "금액을 보여줄 수 없다"** 고 말한다. 틀린 금액을 보여주는 것보다 안 보여주는 것이 낫다.
- **담당자에게는 확인할 곳을 알려준다.** 원인을 단정하지 않고 연결과 가격 데이터 둘 다 적는다.
  다시 눌러도 안 되는 종류의 오류임을 함께 적는다.
- 두 화면 모두 **다시 시도** 버튼(`reset`)과 빠져나갈 링크를 둔다.
- **계산이 실패하면 금액 자리를 비워 두지 않는다.** 응답이 500 이거나 아예 오지 않으면
  "금액을 계산하지 못했습니다" 를 띄우고, 견적 요청 버튼은 열지 않는다.

## 이유

- **메시지를 숨기는 이유는 두 가지다.** 하나는 고객이 읽을 문장이 아니라서이고,
  다른 하나는 옵션·할인 코드가 **가격 규칙의 구조를 알려주기** 때문이다.
  `/q/[publicId]` 는 인증이 없는 공개 주소다. (ADR-0013 이 연락처를 안 찍는 것과 같은 이유다.)
  운영 빌드의 Next.js 는 메시지를 알아서 지우지만, **우리가 안 쓰는 것이 확실한 방법이다.**
- **`digest` 를 보여주는 이유.** 고객이 "오류가 났다"고만 말하면 담당자가 어느 요청인지 못 찾는다.
  `digest` 를 전해 주면 서버 로그에서 바로 그 예외를 집을 수 있다. 숫자 하나로 비밀은 새지 않는다.
- **고객과 관리자 문구를 나누는 이유는 할 수 있는 일이 다르기 때문이다.**
  고객은 기다리는 것 말고 할 수 있는 게 없다. 담당자는 연결과 가격 규칙을 고칠 수 있다.
  둘 다에게 "잠시 후 다시 시도해 주세요"라고 하면, 담당자는 **고칠 수 있는 오류를 두고
  새로고침만 반복한다.**
- **그래도 담당자 화면이 원인을 단정하지는 않는다.** 처음에는 "가격 데이터를 확인하라"고만 썼는데,
  DB 를 내려서 확인해 보니 그 문구가 그대로 떴다. 연결이 끊긴 상황에서 가격 규칙을 뒤지게 만든다.
  **화면은 어느 쪽인지 모른다.** 확인할 곳 두 군데를 적고, 판별은 `digest` 로 로그에서 한다.
- **그래도 `reset` 버튼을 두는 이유.** 모든 예외가 데이터 오류는 아니다. DB 연결이 잠깐 끊긴
  경우라면 다시 누르면 된다. 대신 담당자 화면에는 "같은 화면이 다시 나오면 데이터 문제"라고 적는다.
- **`not-found` 를 따로 만드는 이유.** 404 는 오류가 아니다. 주소가 틀렸거나,
  유효기간이 한참 지나 지워진 견적이다. (ADR-0013 의 파기 대상이 되면 실제로 사라진다)
  "오류가 발생했습니다"라고 하면 고객이 담당자에게 전화한다. 사실대로 "없는 주소"라고 말한다.

- **계산 실패 문구에도 원인을 쓰지 않는 이유는 같다.** 500 응답의 본문에는 내부 메시지가 들어 있을
  수 있다. 본문을 읽어 화면에 옮기지 않고, **상태 코드만 보고** 고정 문구를 띄운다.
  위반 목록(`violations`)과 섞지도 않는다. 그건 고객이 선택을 바꿔서 풀 수 있는 것이고,
  계산 실패는 그렇지 않다.

## 하지 않기로 한 것

- **`app/global-error.tsx`.** 루트 레이아웃(`app/layout.tsx`)이 던질 때만 쓰이는 화면인데,
  이 레이아웃은 데이터를 읽지 않는 정적 JSX 다. 던질 수 없는 경우를 위한 화면은 만들지 않는다.
  레이아웃이 데이터를 읽기 시작하면 그때 만든다.
- **예외 화면에서 로그 보내기.** 서버 예외는 Next.js 가 이미 서버 로그에 남긴다.
  클라이언트에서 한 번 더 보내면 같은 사건이 두 줄이 되고, 보낼 곳(APM)도 아직 없다.
- **예외 종류별 화면 분기.** 종류를 나누려면 예외 클래스부터 만들어야 하고, 화면이 종류를 안다는 것은
  곧 화면이 내부 구조를 안다는 뜻이다. 판별은 `digest` 로 서버 로그에서 한다.
- **`/api/estimate` 에서 예외를 잡아 JSON 으로 바꾸기.** 잡으면 메시지를 응답에 담고 싶어지고,
  그 응답은 인증 없는 공개 경로로 나간다. 잡지 않고 500 으로 두는 편이 샐 구멍이 없다.
- **고객 화면에 문의 연락처 넣기.** 담당자 연락처가 정해진 적이 없다. 추측해서 적지 않는다.
  `QUOTE_SUPPLIER_CONTACT` 가 있지만 그건 견적서 발행처 표기용이다. (ADR-0016)
- **`loading.tsx`.** 예외와 다른 주제다. 지금 느린 화면이 보고된 적 없다.

## 영향

- 예외가 나도 **레이아웃과 스타일이 유지된다.** `error.tsx` 는 Client Component 여야 하고
  (`reset` 을 받으려면 필요하다) 해당 세그먼트의 레이아웃 안에서 렌더링된다.
- `app/admin/error.tsx` 가 있으면 관리자 경로의 예외는 거기서 멈춘다. 고객 화면까지 올라가지 않는다.
- 개발 모드에서는 Next.js 개발 오버레이가 여전히 먼저 뜬다. 우리 화면은 그 뒤에 있다.
  **운영 빌드로 확인해야 실제로 보이는 화면을 본다.** 확인용 설정을 `.claude/launch.json` 의
  `quote-calculator-prod` 로 넣어 뒀다.
- **`error.tsx` 가 뜨는 경우는 지금 인프라 장애뿐이다.** 서버 렌더링 경로가 가격 규칙 해석을
  지나지 않기 때문이다. `/q/[publicId]` 가 재계산을 시작하거나 `/admin` 이 미리보기를 서버에서
  그리면 그때부터 가격 데이터 오류도 이 화면으로 온다.
