# ADR-0018. 견적 요청 시 개인정보 수집·이용 동의를 받고, 동의 시각을 견적에 남긴다

- 상태: 수락됨
- 날짜: 2026-10-07
- 관련: ADR-0013, F-2-2, Q-5, `.claude/rules/ui.md`

## 배경

ADR-0013 은 **무엇을 수집할지**만 정했다. 이름·휴대폰은 필수, 이메일은 선택, 보관은 1년 / 확정 5년.
그런데 **어떻게 동의를 받을지**는 아무도 정하지 않았고, 요청 폼에는 동의 절차도 처리방침 링크도 없었다.

개인정보보호법은 수집 전에 목적·항목·보유기간·동의 거부 권리를 알리고 동의를 받으라고 한다.
동의를 받았다는 사실 자체도 증명할 수 있어야 한다. 지금 상태로 공개하면 첫 고객의 이름을 받는
순간 위법이다. 기능이 모자란 것이 아니라 **공개 요건이 비어 있던 것**이다.

고지 문구를 쓰다가 ADR-0013 과 어긋나는 두 지점이 드러났다.

1. 초안 문구의 수집 항목에 이메일이 없었다. 폼은 이메일을 받는다. **고지에 없는 항목을 받으면 안 된다.**
2. 초안 문구의 보유기간이 "문의 처리 완료 후 파기"였다. 실제 정책은 1년 / 확정 5년이다.
   `CONFIRMED` 5년은 전자상거래법상 보존 의무라 줄일 수 없다. **고지와 실제가 다르면 고지가 거짓이 된다.**

## 결정

**요청 폼에 아래 고지를 띄우고, `[필수]` 체크박스 하나로 동의를 받는다. 동의 시각을 견적 행에 저장한다.**

고지 문구는 다음으로 확정한다. 두 충돌은 **고지를 실제 정책에 맞추는 방향**으로 해소했다.

| 구분 | 내용 |
| ---- | ---- |
| 수집·이용 목적 | 견적 신청자 확인 및 입력한 조건에 따른 견적 결과 제공 |
| 수집 항목 | 이름, 휴대전화번호 (필수) / 이메일 (선택) |
| 보유·이용 기간 | 견적 생성 후 1년. 견적이 확정된 경우 확정 후 5년 (전자상거래법상 계약·결제 기록 보존) |
| 동의 거부 권리 | 동의를 거부할 수 있습니다. 다만 동의하지 않으면 견적 결과 제공이 제한될 수 있습니다. |

- **동의는 저장의 전제 조건이다.** 체크 없이 들어온 요청은 서버가 거부한다(422 아님, 400).
  클라이언트의 `disabled` 버튼은 UX 보조일 뿐이다. (`.claude/rules/ui.md`)
- **동의 시각을 `Quote.privacyConsentAt` 에 저장한다.** 값이 `null` 인 견적은 동의 없이 만들어진 것이고,
  그런 행은 더 이상 생기지 않는다.
- 동의 시각은 `saveQuote(input, now)` 의 `now` 를 쓴다. 서비스 안에서 `new Date()` 를 읽지 않는다.
- 복제 견적(ADR-0014)은 **원본의 동의 시각을 그대로 승계한다.** 복제는 담당자 행위이고,
  고객에게 다시 동의를 받는 행위가 아니다. 새로 수집한 개인정보가 없다.

## 이유

- **체크박스 하나로 끝낸다.** 수집 항목이 연락 수단 셋뿐이고 목적이 하나라 선택 동의로 쪼갤 것이 없다.
  동의를 여러 개로 나누면 고객이 전부 체크하고 아무것도 읽지 않는다.
- **동의 시각을 별 컬럼으로 둔다.** `createdAt` 으로 갈음할 수도 있지만,
  그러면 "동의를 받았는가"와 "행이 언제 생겼는가"가 구분되지 않는다.
  동의 없이 만들어진 과거 행과 동의받은 행을 가려낼 수 없으면 증명이 아니다.
- **동의 시각은 파기 대상이 아니다.** ADR-0013 의 파기는 개인정보 컬럼을 `NULL` 로 비우는 것이다.
  동의 시각은 사람을 특정하지 않고, 지우면 "동의받고 수집했다"는 근거가 함께 사라진다.
  파기 배치를 만들 때 이 컬럼은 건드리지 않는다.
- **고지를 정책에 맞췄다.** 반대 방향(정책을 "처리 완료 후 파기"로 줄이기)은 전자상거래법 보존 의무와
  충돌한다. 지킬 수 없는 약속을 고지하는 쪽이 더 위험하다.

## 하지 않기로 한 것

- **별도 개인정보 처리방침 페이지.** 수집 항목이 셋뿐이라 고지 표가 곧 전문이다.
  링크를 만들면 표와 페이지 두 곳을 따로 관리하게 되고, 둘이 어긋나는 날이 온다.
  수집 항목이 늘거나 제3자 제공·위탁이 생기면 그때 만든다.
- **만 14세 미만 법정대리인 동의.** 요청자는 보호자 또는 본인이고 받는 값은 연락 수단뿐이다.
  학생 정보를 수집하지 않기로 한 ADR-0013 의 결정이 이 절차를 통째로 면하게 해 준다.
  학생 정보를 받기 시작하면 이 결정을 다시 해야 한다.
- **동의 이력 테이블.** 견적 한 건에 동의 한 번이고 철회 기능이 없다. 컬럼 하나로 충분하다.
  철회를 받기 시작하면 이력이 필요해진다.
- **동의 철회 기능.** 철회는 곧 파기 요청이고, 파기 수단 자체가 아직 없다(ADR-0013).
  파기 배치와 함께 결정한다.
- **기존 행 백필.** 운영 데이터가 없다. 개발 DB 의 과거 견적은 `null` 로 남겨 둔다.
  동의 없이 만들어졌다는 사실을 거짓으로 덮지 않는다.

## 영향

- `Quote.privacyConsentAt DateTime?` 추가. nullable 이다. 동의 없이 만들어진 과거 행이 있고,
  "필수"는 ADR-0013 과 같은 방식으로 스키마가 아니라 입력 검증에서 강제한다.
- `saveQuoteSchema` 에 `privacyConsent: z.literal(true)` 가 생긴다.
  `true` 가 아닌 모든 값(누락·`false`·문자열)이 400 이다.
- 운영 공개 전 과제에서 **1번(동의 절차)이 빠진다.** 파기 수단은 그대로 남는다.
