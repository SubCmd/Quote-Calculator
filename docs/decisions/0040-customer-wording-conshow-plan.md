# ADR-0040: 고객 화면 용어는 "컨쇼 플랜", 내부 용어는 "견적" 으로 둔다

- 상태: 승인
- 날짜: 2026-10-15

## 배경

고객에게 보여 주는 이름을 `견적` 에서 `컨쇼 플랜` 으로 바꾼다. 영업상 판단이고,
"견적" 이 공사·견적서의 어감이라 상담 상품과 맞지 않는다는 것이 이유다.

문제는 `견적` 이 화면 문구에만 있는 말이 아니라는 것이다. `Quote` 모델명,
`/q/[publicId]` 주소, `QUOTE_HIDDEN` 같은 감사 로그 액션, 관리자 화면, 그리고
CLAUDE.md 용어표에 모두 들어 있다.

## 결정

**고객이 보는 문구만 바꾼다. 그 외는 전부 `견적` 으로 둔다.**

| 바꾸는 것 | 두는 것 |
| ---- | ---- |
| `/` · `/q/[publicId]` · `/q/[publicId]/print` 의 화면 문구 | 관리자 화면 문구 |
| 브라우저 탭 제목(`layout.tsx` 메타데이터) | `Quote`·`QuoteItem` 모델명, 컬럼명 |
| 개인정보 수집·이용 동의문의 문구 | `/q/` 주소, `publicId` |
| | `AuditAction` 값과 감사 로그 요약 문구 |
| | 코드의 식별자·주석, 문서, CLAUDE.md 용어표 |

주요 대응은 이렇다.

| 기존 | 바뀜 |
| ---- | ---- |
| 견적 계산기 | 나만의 컨쇼 플랜 찾기 |
| 견적 요약 | 맞춤형 플랜 요약 |
| 견적서 (고객이 보는 제목) | 컨쇼 플랜 |
| 견적번호 | 플랜 번호 |
| 견적 요청 | 플랜 요청 |

## 이유

### 왜 주소를 바꾸지 않는가

`/q/[publicId]` 는 고객이 받아 보관하는 링크다. 주소를 바꾸면 **이미 나간 링크가
전부 끊긴다.** 확정 견적은 5년 보존 대상이고(ADR-0022), 그 기간 내내 열려 있어야
한다. 화면 제목이 "컨쇼 플랜" 인데 주소가 `/q/` 인 것은 고객이 신경 쓰지 않는다.

### 왜 모델명·감사 로그를 바꾸지 않는가

이름을 바꾸면 마이그레이션이 생기고, 과거 감사 로그의 액션 값과 새 값이 갈라진다.
`QUOTE_HIDDEN` 과 `PLAN_HIDDEN` 이 섞인 로그는 둘 다 찾아야 읽을 수 있다.
기록은 한 가지 이름으로 남아 있어야 쓸모가 있다.

### 왜 관리자 화면은 그대로인가

담당자가 읽는 화면이고, 코드·DB·로그와 같은 말을 쓰는 쪽이 장애 대응에서 빠르다.
고객용 호칭은 영업이 바꿀 수 있는 것이고 내부 용어는 그렇지 않다. 둘을 묶어 두면
다음에 호칭이 또 바뀔 때 DB 까지 따라 바꿔야 한다.

### 왜 동의문도 바꾸는가

개인정보 수집·이용 동의는 고객이 읽고 동의하는 문서다. 화면은 "컨쇼 플랜" 인데
동의문만 "견적" 이면 무엇에 동의하는지 어긋난다. 수집 항목·보유 기간·목적의
**내용은 바꾸지 않고 호칭만** 맞춘다.

## 대안

- **전부 바꾼다.** 링크가 끊기고 로그가 갈라진다. 얻는 것은 일관성뿐인데,
  그 일관성을 읽을 사람은 코드를 보는 사람 한 명이다.
- **고객 화면도 그대로 두고 로고·브랜드만 바꾼다.** 요청의 핵심이 호칭이라 답이 아니다.

## 영향

- `.claude/rules/ui.md` 에 고객 화면 호칭 절을 추가한다.
- CLAUDE.md 용어표에 "고객 화면에서는 컨쇼 플랜으로 부른다" 를 덧붙인다.
  용어표 자체는 `견적` 을 유지한다. 코드가 그 이름으로 쓰여 있다.
