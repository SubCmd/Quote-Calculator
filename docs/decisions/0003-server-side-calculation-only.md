# ADR-0003: 금액 계산은 서버의 Pricing Service에서만 수행한다

- 상태: 승인
- 날짜: 2026-10-06

## 배경

옵션을 고를 때마다 금액이 즉시 갱신되어야 한다. 브라우저에서 계산하면 응답이 빠르지만,
계산 로직이 클라이언트와 서버 양쪽에 생기고 두 결과가 어긋날 수 있다.
또 클라이언트가 보낸 금액을 그대로 저장하면 조작이 가능하다.

## 결정

계산 로직은 `src/services/pricing/`에만 둔다.
클라이언트는 선택값만 보내고 금액을 받아 표시한다.
견적 저장 시에도 클라이언트가 보낸 금액을 쓰지 않고 서버에서 다시 계산한다.

## 이유

- 계산 로직이 한 곳이라 금액 불일치가 구조적으로 발생하지 않는다.
- 금액 조작을 막는다.
- 가격 규칙 변경이 배포 없이 즉시 반영된다.

## 대안

- 클라이언트 계산 + 저장 시 서버 검증: 로직 이중화. 규칙이 복잡해지면 유지가 어렵다.
- 규칙을 클라이언트로 내려보내 계산: 가격 정책 전체가 노출된다.

## 영향

- 옵션 선택마다 `/api/estimate` 호출이 발생한다. 디바운스와 요청 취소 처리가 필요하다.
- 계산 API 응답 목표를 300ms로 둔다. 가격 규칙 조회에 캐시가 필요할 수 있다.
- UI 컴포넌트에 금액 산술(`*`, `+` 로 합계 만들기)을 작성하지 않는다. 표시 서식만 담당한다.
