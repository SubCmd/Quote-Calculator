# ADR-0013. 견적에는 요청자 연락처만 받고, 학생 정보는 수집하지 않는다

- 상태: 수락됨
- 날짜: 2026-10-06
- 관련: Q-5, `.claude/rules/admin.md`

## 배경

금액 계산만 할 때는 개인정보가 전혀 필요 없다. 선택한 옵션만 있으면 총액이 나온다.
개인정보는 **견적을 저장하고 연락을 받겠다고 할 때** 처음 필요해진다.

대상은 입시 컨설팅이라 실제 수혜자가 미성년자인 경우가 많다.
학생 이름·학교·학년·성적을 받기 시작하면 만 14세 미만 법정대리인 동의 절차가 따라붙고,
민감정보에 가까운 성적 데이터를 보관하게 된다. 견적 금액 산출에는 하나도 쓰이지 않는 값들이다.

## 결정

**요청자 연락처만 받는다. 필수는 이름과 휴대폰 번호 두 개다.**

| 항목 | 필수 | 용도 |
| ---- | ---- | ---- |
| 요청자 이름 | 필수 | 상담 시 호칭 |
| 휴대폰 번호 | 필수 | 상담 연락 |
| 이메일 | 선택 | 견적서 전달 |

- **학생 본인의 정보(이름·학교·학년·성적)는 수집하지 않는다.** 금액 계산에 쓰이지 않는다.
- 보관 기간은 견적 상태로 나눈다.

| 구분 | 기간 | 근거 |
| ---- | ---- | ---- |
| `DRAFT` / `REQUESTED` / `CANCELED` | 생성 후 1년 | 계약으로 이어지지 않은 문의 기록 |
| `CONFIRMED` | 확정 후 5년 | 전자상거래법상 계약·결제 기록 보존 |

- 기간이 지나면 **행을 지우지 않고 개인정보 컬럼만 `NULL` 로 만든다.**
  금액·선택 내역은 통계로 남고, 사람을 특정할 수 있는 값만 사라진다.

## 이유

- **수집하지 않은 정보는 유출될 수 없다.** 가장 싼 개인정보 보호는 안 받는 것이다.
- **미성년자 동의 절차를 통째로 피한다.** 요청자가 보호자든 본인이든,
  받는 값이 "연락할 수단" 뿐이면 절차가 단순해진다.
- **행 삭제 대신 컬럼 비우기**는 삭제보다 비활성화를 기본으로 하는
  `.claude/rules/admin.md` 의 파괴적 작업 규칙과 같은 방향이다.
  견적 건수·금액 통계가 과거 시점으로 소급해 바뀌지 않는다.
- 이메일을 필수로 두면 쓰지 않는 주소를 대충 적어 넣는다. 선택으로 둬야 값이 정확하다.

## 하지 않기로 한 것

- **회원가입·로그인.** 견적 한 건 받자고 계정을 만들게 하지 않는다.
  조회는 추측 불가능한 `publicId` 링크로 한다.
- **자동 파기 배치 구현.** 정책만 정하고 지금은 만들지 않는다.
  운영 데이터가 쌓이기 전에는 돌 일이 없고, 돌지 않는 배치는 썩는다.
  운영 배포 전 과제로 `docs/requirements.md` 에 남긴다.
- **주소·생년월일 수집.** 상담 연락에 필요 없다.

## 영향

- `Quote.customerName` / `customerPhone` / `customerEmail` 은 **nullable 로 유지한다.**
  저장 시에는 이름·휴대폰을 필수로 검증하지만, 파기 시 `NULL` 로 비울 수 있어야 하기 때문이다.
  "필수"는 스키마가 아니라 입력 검증에서 강제한다.
- 관리자 견적 목록에서는 연락처를 마스킹하고, 상세 화면에서만 전체를 보여준다(`.claude/rules/admin.md`).
- 개인정보가 포함된 내보내기는 감사 로그 대상이다. 내보내기 기능을 만들 때 함께 넣는다.
