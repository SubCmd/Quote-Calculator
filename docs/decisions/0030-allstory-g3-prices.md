# ADR-0030. 같은 상담이어도 금액은 상품마다 따로 둔다

- 상태: 수락됨
- 날짜: 2026-10-13
- 관련: ADR-0002, ADR-0006, ADR-0007, ADR-0028, ADR-0029

## 배경

ADR-0029 는 고3 올스토리의 1~4단계가 고2의 3~6단계와 **같은 상담**이라고 보고,
제목·금액·설명을 `ALLSTORY_STAGES` 한 곳에 두고 `slice(2)` 로 나눠 쓰게 했다.
고3 통합등록 금액은 오지 않아서 전단계 할인은 임시 10% 로 남겼다.

그 뒤 고3 확정값이 왔다.

| 고3 | 금액 | 같은 상담인 고2 단계 | 고2 금액 |
| ---- | ---- | ---- | ---- |
| 1단계 | 199,000 | 3단계 | 199,000 |
| 2단계 | 149,000 | 4단계 | 149,000 |
| 3단계 | 249,000 | 5단계 | 249,000 |
| 4단계 | **590,000** | 6단계 | **490,000** |
| 합 | **1,187,000** | | |
| 통합등록 | **1,150,000** | | |

**4단계만 금액이 다르다.** 같은 상담(`수시 6장 대학·학과·전형 최종 지원전략`)인데
고3 쪽이 100,000원 비싸다. ADR-0029 의 "금액까지 공유한다" 가 깨졌다.

## 결정

### 1. 금액은 상품마다 따로 둔다. 공유는 제목·설명까지다

```ts
const ALLSTORY_STAGE_TEXT  // 제목 + 한 문단 설명. 두 상품이 나눠 쓴다
const ALLSTORY_G2_AMOUNTS  // [199,249,199,149,249,490] × 1,000
const ALLSTORY_G3_AMOUNTS  // [199,149,249,590] × 1,000
numberedStages(text, amounts)
```

- 단계 수는 **금액 배열의 길이**가 정한다. 짝이 되는 제목이 없으면 시드가 거부한다.
- ADR-0029 의 결정 1(번호는 상품 안에서 1부터)과 문구 공유는 그대로다.
  **결정 2에서 "금액" 만 빠진다.**

### 2. 고3 통합등록 1,150,000원은 `FIXED` 37,000원 할인으로 둔다

- 단계 합 1,187,000 − 통합등록 1,150,000 = **37,000**.
- 1~4단계 전부 선택이라는 조건은 그대로다. (ADR-0009)
- `RATE 10%` → `FIXED` 종류 변경이라 `scripts/apply-allstory-catalog.ts` 가 한 번 쓴다.
  고2에서 한 것과 같은 경로다. (ADR-0028)

이것으로 임시값이 전부 사라진다. (`docs/requirements.md` Q-9 해소)

## 이유

### 왜 금액이 다른 것을 오기로 보지 않는가

**통합등록 금액이 교차 검증한다.** 4단계가 490,000이면 단계 합은 1,087,000이 되고,
통합등록 1,150,000이 단계 합보다 **비싸진다.** 묶어 사면 더 내는 가격표는 성립하지 않는다.
590,000일 때만 단계 합(1,187,000)이 통합등록보다 크고, 차액 37,000도 10원 단위다.

같은 상담의 값이 상품마다 다른 것은 이상한 일이 아니다. 고3 올스토리에서 그 상담은
**마지막 단계이자 결과물**이고, 고2 쪽에서는 여섯 단계 중 하나다. 묶음 구성이 다르면
개별 금액도 다르게 매길 수 있다.

### 왜 금액을 아예 상품 쪽으로 옮기는가

예외를 `slice` 뒤에 덮어쓰는 방법(`{ ...stage, amount: 590_000 }`)도 가능하다.
그러면 금액이 **두 곳**에 있게 된다. 공유 배열의 490,000과 덮어쓰는 590,000 중
어느 쪽이 그 상품의 값인지 읽는 사람이 코드를 따라가 봐야 안다.

ADR-0029 가 금액까지 공유한 이유는 "한쪽만 갱신되는 상태를 막는다" 였다. 그 전제는
**두 값이 항상 같다**는 것이었고, 지금 깨졌다. 전제가 깨진 공유는 보호가 아니라
거짓 안심이다. 상품별 배열 두 개는 "다를 수 있다"를 그대로 드러낸다.
`ALLSTORY_G3_AMOUNTS` 한 줄을 보면 그 상품의 네 금액이 전부 보인다.

제목과 설명은 계속 공유한다. 그쪽은 **같은 상담이면 같은 문구**라는 전제가 유효하다.
문구가 갈라지는 것은 운영 사고이고, 금액이 갈라지는 것은 가격 정책이다.

### 왜 또 정액인가

ADR-0028 과 같은 이유다. 1,187,000 에서 1,150,000 을 만드는 비율은 3.1171% 로
아무 뜻이 없고, 만분율 정수로는 311bp(36,915 → 버림 36,910)밖에 담기지 않아
총액이 1,150,090 이 된다. 금액 오차 0(`docs/requirements.md` N-2)을 못 맞춘다.

통합등록 금액은 두 상품 모두 **따로 정해진 값**이고, 할인액은 그 값을 맞추기 위한 차액이다.

### 왜 단계 수를 금액 배열이 정하는가

고3은 `ALLSTORY_STAGE_TEXT.slice(2)` 로 제목 네 개를 받는다. 금액 배열이 세 개뿐이면
네 번째 단계가 조용히 사라지고, 다섯 개면 다섯 번째가 제목 없이 만들어진다. 둘 다
**금액이 틀린 상품**이 되고 시드는 성공한다. 짝이 맞지 않으면 거부하는 쪽이 낫다.

## 하지 않기로 한 것

- **고3 4단계를 490,000으로 맞춰 적기.** 사용자가 준 값은 590,000이고, 통합등록
  금액이 그 값을 뒷받침한다. 490,000이면 통합등록이 단계 합보다 비싸진다.
- **공유 배열에 금액을 두고 고3만 덮어쓰기.** 같은 금액이 두 곳에 생긴다.
- **제목·설명도 상품별로 쪼개기.** 그쪽 전제는 깨지지 않았다. 문구는 같아야 한다.
- **비율 할인.** 1,150,000 을 만들지 못한다. 위 이유.
- **할인 행 교체.** 기존 `ALL_STAGES` RATE 행은 지우지 않고 새 버전을 INSERT 한다. (ADR-0002)
- **관리자 화면에 할인 종류 변경 경로 추가.** ADR-0028 그대로다.

## 영향

- `prisma/seed.ts`: `ALLSTORY_STAGES` → `ALLSTORY_STAGE_TEXT` + 상품별 금액 배열.
  `numberedStages(text, amounts)` 로 인자가 둘이 된다.
- `docs/pricing-rules.md` 9-4-1 이 임시값에서 확정값으로 바뀐다.
  소계 1,187,000 / 할인 37,000 / 총액 **1,150,000**.
- `docs/requirements.md` Q-9 가 해소된다. **네 상품 모두 확정값이다.**
- 운영 데이터: 고3 올스토리 4단계에 새 금액 버전(1·2·3단계는 금액이 같아 4단계만 바뀜),
  `ALL_STAGES` 할인의 FIXED 새 버전.
- 스키마 변경 없다.
