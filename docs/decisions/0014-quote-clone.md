# ADR-0014. 견적 복제는 선택만 가져오고 금액은 현재 규칙으로 다시 계산한다

- 상태: 수락됨
- 날짜: 2026-10-07
- 관련: ADR-0002, ADR-0003, ADR-0012, `.claude/rules/admin.md`

## 배경

확정된 견적은 수정하지 않는다(`CLAUDE.md` 6번). `.claude/rules/admin.md` 는 그래서
`CONFIRMED` 견적을 고치는 UI 대신 **"복제해서 새 견적"** 동작만 제공하라고 정해 두었다.

그런데 "복제"가 무엇을 복제하는지는 정해져 있지 않았다. 후보가 둘 있다.

1. **금액까지 그대로 복사** — 원본과 똑같은 금액의 새 행을 만든다.
2. **선택만 복사하고 다시 계산** — 상품·옵션 선택을 가져와 지금 가격 규칙으로 계산한다.

만료된 견적을 되살리고 싶을 때(ADR-0012)도 같은 동작이 쓰인다.

## 결정

**복제는 상품·옵션 선택과 고객 연락처만 가져오고, 금액은 복제 시점의 가격 규칙으로 다시 계산한다.**

- 원본의 `snapshot.input`(`productId`, `optionIds`)을 그대로 입력으로 쓴다.
- 금액·할인·유효기간은 **새로 계산한다.** 저장 경로는 고객이 요청할 때와 같은
  `estimate()` → `createQuote()` 다. 금액을 복사하는 코드 경로를 만들지 않는다.
- 고객 연락처(이름·휴대폰·이메일)는 승계한다. 같은 사람에게 다시 받을 이유가 없다.
- 새 견적의 상태는 `REQUESTED` 다. 원본의 상태는 따라가지 않는다.
- **원본은 전혀 건드리지 않는다.** 상태도 금액도 그대로 둔다.
- 새 견적의 스냅샷에 `clonedFromPublicId` 를 남겨 어디서 왔는지 추적할 수 있게 한다.
- 지금 규칙으로 계산할 수 없는 선택(옵션이 비활성화됐거나 사라진 경우)이면
  **복제하지 않고 위반 목록을 보여준다.** 0원이나 옛 금액으로 저장하지 않는다.

## 이유

- **금액 복사는 ADR-0003 을 우회하는 통로가 된다.** "서버에서 다시 계산한다"는 규칙에
  예외를 하나 만들면, 그 경로로 과거 금액이 새 견적에 들어온다. 복제본은 새로 발행한
  견적이므로 발행 시점 가격이 맞다.
- **옛 금액을 유지하는 수단은 이미 있다.** 원본이 그대로 남아 있고 조회도 된다(ADR-0002).
  같은 금액이 필요하면 원본 주소를 쓰면 된다. 복제는 "지금 다시 견적을 낸다"는 뜻이다.
- **유효기간 계산이 자동으로 맞는다**(ADR-0012). 금액을 복사하면 `calculatedAt` 을
  언제로 둘지 애매해지고, 만료된 견적을 복제했을 때 복제본도 만료된 채로 태어난다.
- 계산할 수 없는 선택을 조용히 통과시키면, 사라진 옵션이 금액 0원으로 둔갑한다.
  "계산 불가"와 "0원"은 다르다(`.claude/rules/pricing.md`).

## 하지 않기로 한 것

- **복제 시 선택 수정.** 관리자가 옵션을 바꿔 가며 복제하는 화면은 만들지 않는다.
  금액이 달라져야 하면 고객용 계산기에서 새로 고르는 것이 같은 일을 더 적은 코드로 한다.
- **연락처를 비운 채 복제.** 다른 고객에게 같은 구성을 제안하는 경우는
  요구로 나온 적이 없다. 필요해지면 복제 후 연락처 수정 기능이 따로 필요하다.
- **원본에 "복제됨" 표시 컬럼 추가.** 추적은 복제본의 스냅샷과 감사 로그로 충분하다.
  원본을 수정하지 않는다는 원칙을 컬럼 하나 때문에 깨지 않는다.

## 영향

- `AuditAction` 에 `QUOTE_CLONED` 가 필요하다. 개인정보를 복사하는 작업이므로
  기록을 남기고, 생성과 기록은 같은 트랜잭션에서 수행한다(`.claude/rules/admin.md`).
- 복제본의 금액이 원본과 다를 수 있다. 관리자 화면은 복제 직후 **새 견적의 금액을**
  보여주어야 하고, 원본과 같을 것이라고 안내해서는 안 된다.
- 가격이 오른 뒤 복제하면 금액이 올라간다. 이것은 버그가 아니라 의도다.
