# ADR-0027. 과정 컨설팅의 추가 옵션은 네 번째 그룹으로 둔다

- 상태: 수락됨
- 날짜: 2026-10-13
- 관련: ADR-0008, ADR-0009, ADR-0010, ADR-0023, ADR-0025, ADR-0026

## 배경

과정 컨설팅의 실제 상품표가 확정됐다. 금액과 문구 교체는 기존 경로(새 금액 버전 `INSERT`,
설명 덮어쓰기)로 끝나지만 하나가 남는다. **회차 중간에 끼워 넣는 모의고사 성적 분석**
(30분 59,000원)을 고를 수 있어야 하고, 나중에 생기부 첨삭도 같은 자리에 들어온다.

지금 과정 컨설팅의 그룹은 셋이고 **전부 `singleSelect`** 다.

| 그룹 | 선택 방식 | 선행 |
| ---- | ---- | ---- |
| 회차 | 하나 | — |
| 소통 방식 | 하나 | 회차 |
| 수행평가 자료 요청 | 하나 | 회차 |

## 결정

### 1. `EXTRA` "추가 옵션" 그룹을 새로 만든다

- `singleSelect: false`, `required: false`, `dependsOn: SESSIONS`, 맨 아래 자리.
- 첫 옵션은 `MOCK` `모의고사 성적 분석 (30분)` 59,000원.

### 2. 1회성 컨설팅의 모의고사 분석과 **별개 행**으로 둔다

코드는 양쪽 다 `MOCK` 이지만 그룹이 다르므로 서로 다른 옵션이다.

### 3. 생기부 첨삭은 이번에 넣지 않는다

금액과 소요 시간이 미정이다. 그룹이 생겼으므로 관리자 화면의 신규 옵션 등록(ADR-0023)으로
나중에 넣을 수 있고, 그때 코드 수정은 필요하지 않다.

## 이유

### 왜 기존 그룹에 넣지 않는가

세 그룹이 전부 단일 선택이다. 거기 넣으면 추가 옵션을 고르는 순간 회차나 소통 방식
선택이 **풀린다.** "추가"는 다른 선택을 대체하지 않는다는 뜻이고, 단일 선택 그룹은 정확히
대체하는 그룹이다. 회차 그룹을 복수 선택으로 바꾸는 길도 있지만 그러면 3회차와 6회차를
동시에 고를 수 있게 된다.

### 왜 선행을 회차로 두는가

추가 옵션은 과정 **중간에** 끼워 넣는 상담이다. 회차를 고르지 않은 채 추가 옵션만 담긴
견적은 뜻이 없다. 소통 방식·수행평가 자료가 회차를 선행으로 갖는 것과 같은 선이다. (ADR-0010)

선행이 생기면 회차 선택이 풀릴 때 추가 옵션 선택도 함께 지워진다. 이미 구현된 연쇄
정리(ADR-0010)가 그대로 적용되고, 표시 순서에서 회차보다 위로 올릴 수 없다(ADR-0026).

### 왜 1회성의 모의고사 분석을 재사용하지 않는가

견적 한 건에는 **상품 하나만** 담는다. (`docs/requirements.md` 3절) 과정 컨설팅 견적에서
1회성 옵션을 고를 경로가 없고, 만들면 그 규칙이 깨진다. 옵션은 상품에 딸린 가격 규칙이라
상품마다 자기 버전 행을 갖는 것이 정상이다.

금액이 같은 것은 지금 상태일 뿐이다. 한 행을 공유하면 1회성 모의고사 분석 금액을 고치는
순간 과정 컨설팅 금액도 같이 움직이고, 그것을 의도한 적이 없다.

### 왜 코드를 `MOCK` 으로 같게 쓰는가

옵션 `code` 는 `(groupId, code)` 로 유일하다. 그룹이 다르면 충돌하지 않는다. 할인 조건도
옵션 코드를 그룹과 함께 들고 있어서(ADR-0009) 모호해지지 않는다. 같은 상담을 가리키는
코드를 상품마다 다르게 적을 이유가 없고, 다르게 적으면 나중에 둘을 대조하기 어려워진다.

### 왜 그룹을 관리자 화면에서 만들게 하지 않는가

ADR-0023 그대로다. 그룹 구조는 상품 설계이고 금액 운영이 아니다. 그룹을 만들려면
`singleSelect`·`required`·`dependsOnGroupId` 를 함께 정해야 하는데, 이 셋을 잘못 고르면
고객 화면의 선택 규칙이 통째로 달라진다. 이번 그룹은 시드와 일회성 스크립트로 넣는다.

## 하지 않기로 한 것

- **회차 그룹을 복수 선택으로 바꾸기.** 3회차와 6회차를 동시에 고를 수 있게 된다.
- **추가 옵션을 할인으로 표현.** ADR-0026 그대로. 금액은 따로 정해진 값이다.
- **옵션 행을 상품 간에 공유.** 한쪽 금액 수정이 다른 쪽으로 번진다.
- **추가 옵션을 선행 없이 두기.** 회차 없는 추가 옵션 단독 견적이 만들어진다.
- **그룹 신설을 관리자 화면에 열기.** ADR-0023 그대로.

## 영향

- `prisma/seed.ts` 에 그룹 하나와 옵션 하나가 늘어난다. **스키마 변경은 없다.**
- 과정 컨설팅 금액의 미확정 범위가 사라진다. 3회차 580,000 / 카톡 소통 390,000 /
  이메일 소통 99,000 으로 교체되고, 6회차 1,100,000 과 5건·10건은 그대로다.
  카톡 300,000 · 이메일 100,000 은 확정값으로 적혀 있었으나 이번에 개정됐다.
  (`docs/requirements.md` Q-9 에서 과정 컨설팅이 빠진다)
- `docs/pricing-rules.md` 9-3 기준값이 1,850,000 → 1,940,000 으로 바뀌고, 계산 테스트도
  같이 갱신한다.
- 선행 그룹 표에 `추가 옵션 → 회차` 한 줄이 늘어난다.
- 운영 데이터는 일회성 스크립트로 넣는다. 그룹 생성은 Service 에 경로가 없으므로
  그 스크립트만 Prisma 를 직접 쓴다. 금액·설명은 기존 Service 를 거쳐 감사 로그를 남긴다.
