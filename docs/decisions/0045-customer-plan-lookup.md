# ADR-0045. 고객은 이름과 휴대전화번호로 자기 플랜을 찾는다

- 상태: 수락됨
- 날짜: 2026-10-16
- 관련: ADR-0012, ADR-0013, ADR-0015, ADR-0018, ADR-0020, ADR-0022, ADR-0024, ADR-0033, ADR-0035, ADR-0040

## 배경

관리자가 `요청접수` · `확정` · `취소` 를 누르면 그 변화를 고객이 알 방법이 지금은 하나뿐이다.
플랜을 요청한 직후 화면에 나온 `/q/{publicId}` 주소를 **직접 보관**하는 것이다.

그 주소는 길고, 요청 직후 한 번만 보인다. 브라우저를 닫거나 다른 기기에서 열면 다시 찾을
길이 없다. 고객은 자기가 요청을 넣었는지, 그게 확정됐는지 확인할 수 없고 전화로 묻게 된다.

문자·이메일 **발송 수단이 없다.** 그래서 "링크를 다시 보내드립니다" 는 선택지가 아니다.
보내지 않는 것을 목적에 적지 않는다는 ADR-0018 의 선도 그대로다.

남는 길은 고객이 **이미 입력한 것으로 다시 찾는 것**이다. 요청 폼이 받는 개인정보는
이름과 휴대전화번호뿐이고(ADR-0013), 둘 다 본인이 기억하고 있다.

## 결정

### 1. `/q/lookup` 에서 이름과 휴대전화번호를 **둘 다** 받고, **정확히 일치**해야 찾는다

- 둘 다 필수다. 하나만으로는 찾지 않는다.
- 이름은 `trim` 후 완전 일치, 전화번호는 **숫자만 남겨** 완전 일치다. 저장도 숫자만이다.
  (`src/lib/validation/quote.ts`)
- 부분 일치·유사 검색을 하지 않는다. 관리자 목록의 이름 검색(ADR-0015)과 다른 화면이다.
  저쪽은 로그인한 사람이 자기 고객을 훑는 것이고, 이쪽은 **인증 없는 공개 경로**다.

### 2. 요청은 `POST` 다. 이름·전화번호를 URL 에 담지 않는다

- `GET /q/lookup?name=...&phone=...` 로 만들지 않는다. 쿼리 파라미터는 브라우저 방문 기록,
  서버 접근 로그, 바깥 링크를 눌렀을 때의 `Referer` 에 남는다.
- 결과도 URL 에 남기지 않는다. 화면 상태로만 들고 있다. 공유할 수 있는 주소는
  개별 플랜의 `/q/{publicId}` 하나다.
- `.claude/rules/ui.md` 의 "URL로 공유·복원이 필요한 선택값은 쿼리 파라미터에 둔다" 는
  선택값 이야기다. 개인정보는 공유·복원 대상이 아니다.

### 3. 결과에는 **이미 고객 것인 정보**만 담는다

| 담는 것 | 담지 않는 것 |
| ---- | ---- |
| 플랜 번호(`publicId`) | 이름·전화번호·이메일 |
| 상품명 | 고른 옵션 목록 |
| 총액 (현금가) | 할인 내역·계산 근거 |
| 상태 (`요청 접수` · `확정` · `취소` · `유효기간 지남`) | 관리자 메모·내부 식별자 |
| 요청한 날짜 | |

- 입력한 이름·전화번호를 화면에 되돌려 적지 않는다. 맞혔다는 사실만 확인시켜 준다.
- 자세한 내역은 `/q/{publicId}` 링크로 간다. 같은 내용을 두 화면에 적지 않는다.
- 상태 표기는 `displayStatus` 가 만든다. `EXPIRED` 는 저장되지 않고 파생된다. (ADR-0012)
  **상태 코드를 화면에 내려보내지 않는다.** 서버가 `statusLabel` 로 옮긴 문구를 보낸다.
  화면이 코드로 분기하는 표를 또 들고 있을 이유가 없다.
- 최근 20건까지 돌려준다. 무제한 조회를 만들지 않는다. (`.claude/rules/database.md`)
  한 사람이 요청한 플랜이 그보다 많은 경우는 없다. 쪽 넘기기를 두지 않는 이유다.

### 4. 숨긴 플랜은 나오지 않는다

`hiddenAt` 이 있는 플랜은 목록에서 제외한다. 관리자가 보지 않기로 한 플랜의 고객 링크도
함께 닫히기 때문이다. (ADR-0035) 조회만 열어 두면 닫은 뜻이 없어진다.

파기된 플랜(ADR-0022)은 이름·전화번호가 비어 있어 **자연히 걸리지 않는다.** 따로 조건을
적지 않는다. 대신 빈 입력을 서버가 먼저 막는다. 빈 문자열이 `null` 과 맞아떨어지는 길을
만들지 않기 위해서다.

### 5. 못 찾은 이유를 말하지 않는다

이름이 틀렸는지, 전화번호가 틀렸는지, 애초에 그런 플랜이 없는지를 나눠 적지 않는다.
한 문구다.

> 입력하신 정보와 일치하는 컨쇼 플랜을 찾지 못했습니다.

나눠 적으면 `이름은 맞다` 가 응답으로 새어 나간다. 남은 시도 횟수를 알려주지 않는
ADR-0020 과 같은 선이다.

### 6. 시도 제한은 **IP 한도만** 둔다. 전체 한도를 두지 않는다

- 10분 창, 같은 IP 10회 **실패**에 닿으면 조회하지 않고 `429` 다.
- 성공은 세지 않는다. 자기 플랜을 여러 번 확인하는 것은 막을 일이 아니다.
- **잠긴 동안의 시도를 기록하지 않는다.** 기록하면 창이 계속 새로 채워져 영구 잠금이 된다.
  (ADR-0020 의 보장과 같다)
- 요청자 IP 는 `CF-Connecting-IP` 하나만 읽는다. (ADR-0024)
- 판정은 순수 함수 하나이고 화면·Route 가 조건문을 직접 적지 않는다.

**전체 한도를 두지 않는 것이 ADR-0020 과 다른 점이다.** 관리자 로그인은 전체가 잠겨도
들어오지 못하는 사람이 한 명이지만, 고객 조회가 전체로 잠기면 **그 시간 동안 모든 고객이**
자기 플랜을 못 찾는다. 분산 시도를 막으려고 정상 고객 전부를 막는 쪽이 피해가 크다.

그 자리를 메우는 것은 세 가지다.

1. 두 칸을 **모두** 정확히 맞혀야 한다. 한 칸짜리 대입이 성립하지 않는다.
2. 맞혀도 나오는 것은 이미 그 사람 것인 정보뿐이다. (§3)
3. 모든 조회가 감사 로그에 남아 비정상 패턴을 뒤에서 읽을 수 있다. (§7)

### 7. 조회 사실은 남기고 **조회어는 남기지 않는다**

- `AuditAction.QUOTE_LOOKED_UP` 을 추가한다. `actor` 는 `"customer"` 다.
- 이름·전화번호를 담지 않는다. 결과 건수만 적는다. 저장하지 않으면 파기할 것도 없다.
  (ADR-0015, ADR-0022, ADR-0041 과 같은 선)
- 0건도 남긴다. 못 찾은 시도가 쌓이는 것이 읽어야 할 신호다.
- **잠겨서 거부한 요청은 남기지 않는다.** 막은 요청이 로그를 밀어내게 두지 않는다.

### 8. 시도 기록은 **별도 테이블**이다

`QuoteLookupAttempt` 를 만들고 `AdminLoginAttempt` 를 같이 쓰지 않는다. 한 테이블을 쓰면
고객의 오타가 관리자 로그인을 잠그고, 관리자 로그인 실패가 고객 조회를 잠근다. 한도와
창 길이도 서로 다르다.

두 테이블의 시간 계산(마지막 실패 기준으로 창 길이만큼 잠금, 최소 1초)은 같은 식이므로
`src/lib/attempt-window.ts` 한 곳에 두고 양쪽이 쓴다. 같은 식을 두 번 적지 않는다.

## 이유

### 왜 이름과 전화번호 **둘 다** 인가

- 전화번호만으로 열면 번호 하나를 아는 사람이 남의 플랜 목록을 연다. 11자리는 순차 대입이
  가능한 공간이고, 실제로 쓰이는 앞자리는 그보다 훨씬 좁다.
- 이름만으로 열면 동명이인이 서로의 플랜을 본다.
- 둘을 함께 요구하면 **그 사람을 이미 아는 사람**만 조회에 성공한다. 그 수준이 이 데이터에
  맞는 문턱이다. 나오는 것은 "이 사람이 어떤 상담을 요청했고 지금 어떤 상태인가" 이고,
  금액·연락처·상담 내용은 `/q/{publicId}` 쪽에 있다.

### 왜 인증번호·비밀번호를 쓰지 않는가

- **문자 발송 수단이 없다.** 인증번호는 보낼 길이 없어서 성립하지 않는다.
- 플랜마다 비밀번호를 부여하면 고객이 기억할 것이 하나 더 늘고, 그것을 잊었을 때
  되찾는 경로가 또 필요하다. 지금 문제가 "보관하지 못했다" 인데 보관할 것을 늘린다.
- 발송 수단이 생기면 그때 다시 정한다. 그때는 이 화면이 **입력 보조**가 아니라
  대체 경로가 되는 쪽이 맞다.

### 왜 관리자 검색(ADR-0015)과 같은 코드를 쓰지 않는가

관리자 검색은 이름 **부분 일치**로 여러 고객을 훑는다. 로그인한 사람이 자기 고객 목록을
보는 동작이기 때문이다. 같은 질의를 공개 경로에 두면 `김` 한 글자로 전체 명단이 열린다.

두 화면은 목적이 반대다. 하나는 **넓게 찾기**, 하나는 **자기 것만 집기**다. 질의를 공유하면
한쪽의 편의가 다른 쪽의 구멍이 된다.

### 왜 조회 결과에서 상태를 바꾸지 못하게 하는가

조회는 읽기다. 결제 방식 선택은 `/q/{publicId}` 에 그대로 있고(ADR-0033), 거기 가려면
플랜 번호를 맞힌 것이 아니라 **목록에서 자기 플랜을 고른** 것이어야 한다. 목록 화면에
쓰기 동작을 두면 한 번의 오조회가 남의 플랜 상태를 건드린다.

## 하지 않기로 한 것

- **전체(global) 시도 한도.** 공격자 한 명이 전 고객의 조회를 막는 수단이 된다.
- **전화번호만 / 이름만 조회.** 각각 남의 플랜을 열거나 동명이인을 섞는다.
- **부분 일치·유사 검색.** 열거를 쉽게 만든다. 공개 경로에서는 정확히 일치만 받는다.
- **조회 조건을 URL 에 담기.** 기록·로그·`Referer` 에 이름과 번호가 남는다.
- **못 찾은 이유 구분해서 알려주기.** 맞은 칸이 무엇인지 알려주는 셈이다.
- **남은 시도 횟수 알려주기.** ADR-0020 그대로다. 잠긴 사실과 남은 시간만 적는다.
- **숨긴 플랜 보여주기.** 관리자가 닫은 것은 고객 쪽도 닫힌다. (ADR-0035)
- **조회 로그에 이름·전화번호 담기.** 파기할 개인정보를 스스로 만든다. (ADR-0022)
- **조회 화면에서 결제 방식 고르기·취소 요청하기.** 조회는 읽기뿐이다.
- **`AdminLoginAttempt` 테이블 같이 쓰기.** 두 잠금이 서로를 건다.
- **인증번호(SMS)·플랜 비밀번호.** 발송 수단이 없고, 기억할 것을 늘린다.

## 영향

- 스키마: `QuoteLookupAttempt` 모델 1개, `AuditAction.QUOTE_LOOKED_UP` 1개.
  둘 다 추가이므로 백필이 없다. (`.claude/rules/database.md`)
- `src/lib/attempt-window.ts` 가 생기고 `login-throttle.ts` 의 시간 계산이 그리로 옮겨간다.
  ADR-0020 의 한도·창 길이·정책은 그대로다.
- `app/q/lookup/page.tsx` + 입력 위젯(`'use client'`), `app/api/q/lookup/route.ts`.
- 고객이 조회 화면으로 갈 길을 둔다. **첫 화면 머리말과 `/q/{publicId}` 하단 둘이다.**
  요청을 넣으면 곧바로 `/q/{publicId}` 로 이동하므로 따로 완료 화면이 없고, 그 화면이
  곧 요청 직후에 보는 자리다. 주소를 보관하지 못한 고객이 찾아올 자리가 없으면
  화면을 만든 뜻이 없다.
- 문구는 고객 화면이므로 `컨쇼 플랜` 을 쓴다. (ADR-0040)
- `docs/requirements.md` 에 고객 조회 기능이 들어간다.
