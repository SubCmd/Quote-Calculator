# ADR-0050. 목록 내보내기는 CSV 하나이고, 파일에 열쇠를 담지 않는다

- 상태: 수락됨
- 날짜: 2026-10-19
- 관련: ADR-0012, ADR-0013, ADR-0015, ADR-0022, ADR-0039, ADR-0047, ADR-0049,
  `.claude/rules/admin.md`, `.claude/rules/database.md`

## 배경

ADR-0049 가 총계를 붙였고 그것은 **고른 줄의 합**이다. 같은 ADR 이 검색 결과 전체의
합을 두지 않기로 했다. 건수에 상한이 없어서 무제한 조회나 DB 집계를 켜는 길이 되기
때문이다.

그래서 담당자가 할 수 없는 일이 남았다. 연락처별·상태별로 **여러 페이지에 걸친 합**을
구하는 일, 그리고 그 목록을 가지고 화면 밖에서 따로 묶어 보는 일이다. 화면에 숫자를 더
얹는 대신 **목록을 파일로 내려주면** 그 뒤는 엑셀이 한다. 피벗이든 상태별 소계든
담당자가 원하는 축으로 묶을 수 있고, 축이 하나 늘 때마다 화면에 칸을 더하지 않아도 된다.

## 결정

### 1. `.xlsx` 가 아니라 **CSV** 다

`.xlsx` 는 zip + XML 묶음이라 라이브러리 의존이 생긴다. 내보내기 한 기능 때문에 운영
서버에 패키지를 더하고, 그 패키지가 서식·수식까지 쓸 수 있게 되면 **금액 서식이 파일
안에 생긴다.** 그러면 금액을 만드는 자리가 또 늘어난다.

CSV 는 표준 라이브러리만으로 만든다. 엑셀이 더블클릭으로 연다. 대신 세 가지를 맞춘다.

- **UTF-8 BOM** 을 붙인다. 엑셀은 BOM 이 없으면 CP949 로 읽어서 한글이 전부 깨진다.
- 줄 끝은 **CRLF** 다. RFC 4180 이고 엑셀이 기대하는 형태다.
- 값은 항상 `"` 로 감싸고 내부 `"` 는 `""` 로 겹친다. 쉼표·줄바꿈이 든 값을 따로 분기하지 않는다.

### 2. 금액은 **숫자 그대로** 넣는다

파일 안의 총액은 `1490000` 이다. `1,490,000원` 이 아니다.

내보내기를 만든 이유가 엑셀이 `SUM` 하게 하는 것이다. 쉼표와 `원` 이 붙으면 문자열이
되어 더해지지 않고, 담당자는 다시 손으로 고친다. **화면은 포맷하고 파일은 포맷하지
않는다.** `formatKRW` 를 파일 생성 경로에서 부르지 않는다.

이것은 ADR-0049 가 연 예외보다 더 좁다. 더하지도 않는다. 저장된 정수를 그대로 쓴다.

### 3. **`publicId` 를 파일에 넣지 않는다**

`publicId` 는 인증 없는 고객 링크의 주소다. (ADR-0013) 그 값만 알면 `/q/{publicId}`
가 그 고객의 플랜 전체를 보여준다. 목록 전체의 `publicId` 가 든 CSV 는 **파일 한 장이
모든 고객의 견적을 여는 열쇠 묶음**이다. 메일로 돌거나 공유 드라이브에 올라가는
순간 되돌릴 수 없다.

한 건을 자세히 봐야 하면 화면에서 고객명·연락처로 찾는다. 그 경로는 로그인 뒤에 있다.

컬럼은 이 일곱이다.

| 컬럼 | 형태 | 비고 |
| ---- | ---- | ---- |
| 요청일시 | `YYYY-MM-DD HH:mm` | Asia/Seoul. 엑셀이 날짜로 읽는 형태 |
| 상품 | 문자열 | 첫 항목의 상품명. 화면과 같다 |
| 고객명 | 문자열 | 가리지 않는다 (ADR-0047) |
| 연락처 | `010-1234-5678` | **하이픈을 넣는다** |
| 총액 | 정수 | 현금가 (ADR-0039) |
| 결제 방식 | 문자열 | `미선택` 을 그대로 적는다 |
| 상태 | 문자열 | `displayStatus` 를 거쳐 만료를 반영한다 (ADR-0012) |

연락처에 하이픈을 넣는 것은 표기 취향이 아니다. `01012345678` 을 엑셀이 숫자로 읽어
**앞의 0 을 떼어 먹는다.** 하이픈이 있으면 문자열로 남는다.

### 4. 고객명은 **수식으로 해석될 수 있다.** 앞을 막는다

고객명은 고객이 직접 적은 문자열이다. `=`, `+`, `-`, `@`, 탭, CR 로 시작하는 값을
엑셀은 **수식으로 읽는다.** `=cmd|...` 류가 그 자리에 들어오면 파일을 연 담당자의
PC 에서 실행을 묻는 창이 뜬다. 담당자는 자기가 방금 내려받은 자기 회사 파일이라서 누른다.

그래서 그 문자로 시작하는 값 앞에 `'` 를 붙인다. 판정은 **모든 문자열 칸**에 건다.
"고객명만 위험하다" 로 좁히지 않는다. 상품명과 결제 방식은 지금 우리가 정하는 값이지만,
위험한 칸을 사람이 골라내는 방식은 칸이 하나 늘 때 깨진다.

### 5. **행 수 상한이 있다.** 넘으면 파일을 만들지 않는다

`EXPORT_LIMIT = 1000` 이다. 조건에 맞는 건수가 넘으면 CSV 를 만들지 않고 건수와 함께
기간을 좁히라는 사유를 돌려준다.

ADR-0049 가 전체 합을 거부한 이유가 무제한 조회였다. 내보내기는 그 조회를 **해야 하는**
기능이라서, 거부하는 대신 **상한을 명시한다.** 상한 없는 `findMany` 를 두지 않는다는
규칙은 그대로다. 숫자가 하나 적혀 있는 것과 없는 것은 다르다.

페이지네이션을 쓰지 않는다. 내보내기는 한 번의 요청으로 한 파일을 만든다. 1,000행을
`select` 로 좁혀 읽는 것은 한 번이면 괜찮고, 그 한 번을 넘길 만큼 쌓였으면 그때는
기간 단위 집계를 따로 만들 시점이다. (ADR-0049 와 같은 선)

### 6. `QUOTE_EXPORTED` 를 남긴다. **건수만** 적는다

`.claude/rules/admin.md` 가 "개인정보가 포함된 데이터 내보내기" 를 이미 감사 대상으로
적어 두었다. 그 자리를 채운다.

- `AuditAction` 에 `QUOTE_EXPORTED` 를 더한다. `QUOTE_SEARCHED` 와 묶지 않는다.
  목록에서 **읽은 것과 내려받은 것이 바로 구분돼야** 한다. 유출 경위를 따질 때 보는 값이다.
- **조건·고객명·연락처를 남기지 않는다.** 건수와 시각과 누가만 적는다. 검색어를 남기지
  않는 것과 같은 선이다. (ADR-0015, ADR-0022) 감사 로그가 개인정보 저장소가 되면
  파기(ADR-0022)가 로그를 비켜 간다.
- **내보내기에 `QUOTE_SEARCHED` 를 겹쳐 남기지 않는다.** 한 동작에 로그 둘이 남으면
  검색 건수 집계가 거짓이 된다.
- 상한을 넘어 거부한 요청은 남기지 않는다. 내보낸 것이 없다.

### 7. 길은 `GET /api/admin/quotes/export` 하나이고, 검색 조건 파싱은 **한 곳**이다

- 목록 화면의 `내보내기` 는 `<a download>` 링크다. 지금 화면의 쿼리를 그대로 달고 간다.
  JS 를 쓰지 않으므로 Server Component 가 만든다. 클릭 한 번에 지금 보고 있는 조건의
  파일이 내려온다.
- 파일 이름은 `Content-Disposition` 으로 `quotes-YYYYMMDD.csv` 다.
- `status`·`name`·`from`·`to`·`hidden`·`product`·`phone`·`payment` 를 읽는 파서를
  **목록 페이지와 내보내기 라우트가 같은 함수로** 쓴다. 두 번 적으면 그것이 두 번째
  판정이 되고, 화면에서 좁힌 것과 파일에 담긴 것이 어긋난다. 어긋나도 아무 에러가
  나지 않아서 **담당자는 알 수 없다.** 조건 파싱 자체가 보안 경계다.
- `page` 는 읽지 않는다. 내보내기에 페이지가 없다.
- 라우트는 다른 관리자 라우트와 같이 `isAdmin()` 을 다시 확인한다. (ADR-0011)
  미들웨어는 쿠키 존재만 본다.

## 이유

### 화면에 연락처별·상태별 소계를 붙이지 않은 이유

처음 요청은 그것이었다. 두지 않았다.

축이 하나 늘 때마다 표에 줄이 생긴다. 상태 5개 × 결제 방식 4개면 소계 칸이 그만큼이고,
그중 담당자가 이번에 보는 것은 하나다. 그리고 그 숫자들은 **고른 줄의 합인지 검색 결과
전체의 합인지** 매번 다시 설명해야 한다. ADR-0049 가 두 숫자를 나란히 두지 않은 이유가
그것이다.

엑셀은 그 묶음을 담당자가 그때그때 만들게 해 준다. 축을 우리가 미리 고르지 않아도 된다.

### CSV 생성을 Service 가 아니라 `src/lib/csv.ts` 에 둔 이유

따옴표 겹치기·BOM·수식 방어는 **문자열 변환**이고 DB 도 금액도 모른다. 순수 함수라서
테스트가 쉽고, 틀렸을 때 틀린 자리가 하나다. Service 는 조회와 감사 로그를 맡고,
행을 문자열로 바꾸는 일은 그 함수에 넘긴다.

### 비밀번호나 2차 확인을 두지 않은 이유

내보내기는 되돌릴 수 없지만 **파괴적이지 않다.** 지우는 것이 아니라 복사하는 것이다.
ADR-0041 이 `삭제` 에 확인 단계를 둔 이유는 되돌릴 수 없는 손실이고, 여기서는 손실이
없다. 대신 **기록이 남는다.** 위험을 막는 수단이 확인 창이 아니라 감사 로그인 경우다.

## 영향

- `src/lib/csv.ts` 가 새로 생긴다. 순수 함수와 테스트.
- `AuditAction` 에 `QUOTE_EXPORTED` 가 더해진다. 마이그레이션 한 줄.
- 검색 조건 파서가 한 곳으로 모인다. `app/admin/quotes/page.tsx` 가 그것을 쓰도록 바뀐다.
- Repository 에 상한이 명시된 내보내기 조회가 생긴다. `findQuoteList` 와 `where` 를 공유한다.
- `.claude/rules/admin.md` 에 내보내기 절이 생긴다.
- 고객 화면은 바뀌지 않는다.
