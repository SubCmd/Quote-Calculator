# ADR-0044. 선행 조건을 옵션 하나로 좁힐 수 있게 한다

- 상태: 수락됨
- 날짜: 2026-10-16
- 관련: ADR-0009, ADR-0010, ADR-0023, ADR-0037, ADR-0043

## 배경

올스토리에 `대학교 경쟁률 분석(파이널콜)` 을 넣는다. 49만원이고 고2·고3 모두 같은
금액이다. 조건이 있다.

- 고2 올스토리: **6단계를 골랐을 때만** 고를 수 있다.
- 고3 올스토리: **4단계를 골랐을 때만** 고를 수 있다.

두 상품에서 그 단계가 수시 6장 최종 지원전략이다. 지원할 대학을 정하는 상담을
받지 않은 고객에게 그 대학의 경쟁률을 분석해 줄 대상이 없다.

지금 있는 선행 조건은 `OptionGroup.dependsOnGroupId` 하나이고 **그룹 단위**다. (ADR-0010)
그 그룹에 **아무 선택이든 하나 있으면** 충족이다. 파이널콜의 선행을 단계 그룹으로 걸면
1단계만 고른 고객에게도 열린다. 요구와 다르다.

## 결정

### 1. `OptionGroup.dependsOnOptionCode` 를 추가한다

```prisma
/// 선행 그룹에서 **이 코드의 옵션**을 골라야 충족된다. null 이면 그룹에 선택이 있으면 충족 (ADR-0044)
dependsOnOptionCode String? @map("depends_on_option_code")
```

- `dependsOnGroupId` 가 있을 때만 뜻이 있다. 혼자서는 가리킬 그룹이 없다.
- `null` 이 기본이고, 그때는 지금 그대로 **그룹에 선택이 있으면 충족**이다. (ADR-0010)
- 값이 있으면 그 그룹에서 **그 옵션이 선택되어야** 충족이다. 다른 단계를 몇 개
  골랐는지는 보지 않는다.

### 2. 옵션은 **코드**로 가리킨다. 행 id 로 가리키지 않는다

`dependsOnGroupId` 는 행 id FK 다. `OptionGroup` 이 버전 테이블이 아니라서 id 가
안정적이기 때문이다. (ADR-0010)

`ProductOption` 은 **버전 테이블**이다. 금액 버전을 추가하면 새 행이 생기고 id 가
바뀐다. 할인 조건이 코드로 옵션을 가리키는 것과 같은 이유로 여기도 코드다. (ADR-0009)
그래서 FK 를 걸지 않고 `findRuleSet` 이 조회 시점에 해석한다.

### 3. 선행 조건은 그룹 속성이다. 옵션 속성으로 두지 않는다

파이널콜은 **자기 그룹**(`FINALCALL`)을 갖는다. 단계와 성격이 다른 상담이라
단계 그룹 안에 섞지 않는다. ADR-0043 §5 가 이미 그렇게 전제하고 있다.

### 4. 해석되지 않는 선행 옵션은 **닫힌 쪽으로 실패한다**

`findRuleSet` 이 `dependsOnOptionCode` 를 현재 버전의 옵션 id 로 못 바꾸는 경우
(그 옵션이 비활성이거나 코드가 틀렸을 때) **예외를 던지지 않는다.** 대신 그 그룹을
`충족 불가` 로 둬서 선택을 거부한다.

할인 조건은 던진다. (ADR-0009, ADR-0017) 거기서는 조건을 무시하면 **할인이 과하게
걸려** 금액이 틀린다. 여기는 반대다. 조건을 해석할 수 없으면 그 옵션을 **팔지 않는
쪽**이 안전하고, 던지면 상품 전체 계산이 통째로 죽는다. 묶음 안내와 같은 선택이다. (ADR-0037)

### 5. 위반 코드를 따로 둔다

`OPTION_PREREQUISITE_UNMET` 이다. `GROUP_PREREQUISITE_UNMET` 과 메시지가 다르다.
그룹 쪽은 `먼저 '단계' 항목을 선택해 주세요` 이고, 옵션 쪽은 **그 옵션 이름**을 적는다.
`먼저 '6단계 (60~80분)' 을 선택해 주세요` 다. 어느 단계인지 말하지 않으면 고객은
단계 그룹 전체를 다시 훑어야 한다.

해석되지 않는 경우에는 이름이 없으므로 `지금은 선택할 수 없는 항목입니다.` 로 적는다.
없는 옵션 코드를 화면에 노출하지 않는다. (ADR-0021)

### 6. 선행이 풀리면 딸린 선택도 지운다

6단계를 끄면 파이널콜 선택이 함께 사라진다. 그룹 단위 선행과 같은 동작이고,
`pruneUnmetGroups` 가 옵션까지 보도록 바뀐다. (ADR-0010)

## 이유

### 왜 `ProductOption` 에 선행 컬럼을 두지 않는가

파이널콜을 단계 그룹 안에 넣고 그 **옵션 행**에 선행을 적는 길도 있다. 두 가지가 걸린다.

1. `ProductOption` 은 버전 테이블이다. 금액 버전을 추가할 때마다 선행 조건을 새 행에
   다시 적어야 하고, 한 번 빠뜨리면 조건 없는 파이널콜이 조용히 팔린다.
   `sortOrder` · `isActive` 처럼 코드 단위 속성을 모든 버전 행에 같이 쓰는 방식(ADR-0023)을
   또 하나 늘리는 셈이다.
2. 같은 그룹에 들어가면 ADR-0043 의 `모두 선택` 버튼이 파이널콜까지 켠다. 그러면
   조건을 만족하지 않은 선택을 버튼이 만들고, 라벨은 여전히 `모두 선택` 이다.
   ADR-0043 이 옵션 플래그를 거부한 이유가 그대로 돌아온다.

그룹으로 두면 선행 조건이 **한 행에 한 번** 있고, 버튼은 자기 그룹만 켠다.

### 왜 `dependsOnGroupId` 를 그대로 두고 옆에 컬럼을 하나 더 두는가

`dependsOnOptionCode` 만으로 "어느 그룹의 코드인가" 를 알 수 없다. 코드는 그룹 안에서만
유일하다. 과정 컨설팅의 `MOCK` 과 1회성의 `MOCK` 이 다른 옵션인 것과 같다. (ADR-0027)

그룹 id 와 코드 둘을 쌍으로 두면 할인 조건의 `(groupCode, optionCode)` 와 같은 모양이
된다. (ADR-0009) 다른 가리킴 방식을 새로 만들지 않는다.

### 왜 조건 옵션을 여러 개 받지 않는가

`6단계 또는 5단계` 같은 조건은 지금 요구에 없다. 목록으로 받으면 OR 인지 AND 인지를
컬럼 하나가 더 말해야 하고, 그 뜻은 테이블을 봐서는 알 수 없다. 필요해지면
`DiscountCondition` 처럼 **행으로 쪼갠 테이블**을 따로 만드는 쪽이 맞다.
컬럼에 배열을 넣어 두고 나중에 뜻을 바꾸지 않는다.

### 왜 파이널콜을 상품 코드로 분기하지 않는가

고2는 6단계, 고3은 4단계다. 코드로 분기하면 `if (product.code === 'ALLSTORY_G2')` 가
생기고, 그것은 `.claude/rules/pricing.md` 가 금지한 모양이다. 상품마다 다른 것은
**조건 값**이지 로직이 아니라서 데이터로 둔다. 두 상품의 `FINALCALL` 그룹이 각각
`STAGE_6` 과 `STAGE_4` 를 적는다.

## 하지 않기로 한 것

- **옵션 단위 선행 컬럼을 `ProductOption` 에 추가.** 버전마다 다시 적어야 하고
  ADR-0043 의 버튼이 그 옵션을 켠다.
- **조건 옵션 목록(여러 개).** 지금 요구는 하나다. AND/OR 를 컬럼으로 숨기지 않는다.
- **선행 미충족 옵션을 화면에서 숨기기.** `disabled` 로 두고 사유를 적는다. (ADR-0010)
  숨기면 49만원 상담이 존재하는지도 모른다.
- **파이널콜을 단계 그룹에 넣기.** ADR-0043 §5 와 충돌한다.
- **해석되지 않는 선행 옵션에 예외 던지기.** 상품 전체 계산이 죽는다. (ADR-0037)
- **파이널콜 전용 할인.** 요구에 없다. 전단계 할인의 조건은 단계 여섯 개 그대로이고
  파이널콜은 들어가지 않는다.
- **관리자 화면에서 `dependsOnOptionCode` 편집.** 그룹 구조는 상품 설계다. (ADR-0023, ADR-0026)

## 영향

- 스키마: `OptionGroup.dependsOnOptionCode String?`. nullable 이라 백필이 없다.
- `OptionGroupRule` 이 `dependsOnOptionCode` 와 Repository 가 해석한 `dependsOnOptionId`
  둘을 갖는다. **코드가 있는데 id 가 `null` 이면 충족 불가**가 불변식이다.
- `validateSelection` 에 `OPTION_PREREQUISITE_UNMET` 분기가 생긴다.
- `CatalogGroup` 이 선행 옵션의 id 와 이름을 함께 내려보낸다. 화면이 잠금 사유에
  옵션 이름을 적어야 한다.
- `app/quote-form.tsx` 의 `hasSelection` · `pruneUnmetGroups` · 잠금 문구가
  옵션까지 본다.
- 운영 데이터: 두 상품에 `FINALCALL` 그룹과 옵션 `FINALCALL` 490,000원이 생긴다.
  시드와 마이그레이션 양쪽에 같은 값을 넣는다. (ADR-0043 과 같은 방식)
- `docs/requirements.md` 3절 상품 구성과 `docs/pricing-rules.md` 5절 제약 목록이 바뀐다.
