# ADR-0001: 금액은 원 단위 정수로 다룬다

- 상태: 승인
- 날짜: 2026-10-06

## 배경

견적 금액은 1원이라도 틀리면 안 된다. JavaScript의 `number`는 2진 부동소수점이라
`0.1 + 0.2 !== 0.3`처럼 소수 연산에서 오차가 발생한다. 통화는 원화 단일이고 소수 원 단위는 거래에서 쓰이지 않는다.

## 결정

모든 금액을 **원 단위 정수**로 저장·계산·전달한다. Prisma 타입은 `Int`.
요율(할인율·부가세율·가산율)만 `Decimal`로 저장하고, 곱한 직후 정수로 환산한다.

## 이유

- 원화는 최소 단위가 1원이라 정수로 표현 가능한 범위 안에 있다.
- 정수 연산은 오차가 없고, 테스트로 기대값을 고정하기 쉽다.
- `Decimal`을 전 구간에 쓰면 직렬화 경계마다 변환 비용과 타입 혼선이 생긴다.

## 대안

- `Decimal`로 모든 금액 저장: 정밀하지만 원화 단일 통화에서 이득이 없고 JSON 직렬화 시 문자열 변환이 번거롭다.
- `number`(float) 사용: 오차 위험. 기각.

## 영향

- 금액 필드는 `Int`로 선언한다. `Float`/`Decimal` 금액 필드를 만들지 않는다.
- 요율 곱셈 결과는 `src/lib/money.ts`의 헬퍼를 거쳐 정수로 만든다.
- 반올림 지점은 `docs/pricing-rules.md` 2절에 명시된 두 곳뿐이다.
- 다통화(소수 단위 통화) 요구가 생기면 이 ADR을 대체해야 한다.
