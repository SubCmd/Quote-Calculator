# ADR-0011. 관리자 인증은 단일 공유 비밀번호로 시작한다

- 상태: 수락됨 (잠정)
- 날짜: 2026-10-06
- 관련: Q-3, `.claude/rules/admin.md`

## 배경

가격 규칙을 관리자가 직접 고칠 수 있어야 한다(`CLAUDE.md` 4번, `.claude/rules/admin.md`).
그런데 인증 방식(Q-3)은 아직 확정되지 않았다. 확정될 때까지 관리자 화면을 미루면
금액 교체를 계속 `prisma/seed.ts` 수정으로만 해야 한다.

`.claude/rules/admin.md` 는 역할을 `STAFF`(견적 조회·상태 변경)와 `ADMIN`(가격 규칙 변경)으로 나눈다.
지금 구현 범위는 가격 규칙 변경뿐이라 `STAFF` 가 할 일이 없다.

## 결정

**관리자 인증을 `ADMIN` 단일 역할, 환경변수 공유 비밀번호로 구현한다.**

- `ADMIN_PASSWORD` 로 로그인하면 HMAC 서명된 httpOnly 쿠키를 발급한다.
- 서명 키는 `ADMIN_SESSION_SECRET`. 둘 중 하나라도 비어 있으면 관리자 영역은 **전부 차단**된다.
- 인증 판단은 `src/lib/auth.ts` 한 곳에만 둔다. 다른 코드는 "지금 요청이 ADMIN 인가"만 묻는다.
- 감사 로그의 `actor` 는 고정 문자열 `admin` 이다. 개인을 특정하지 못한다는 뜻이다.

## 이유

- **교체 비용을 한 파일로 가둔다.** SSO·OAuth·사용자 테이블 중 무엇으로 가든
  `src/lib/auth.ts` 의 `requireAdmin()` 반환값만 바뀐다. 호출부는 그대로다.
- **기본 차단을 지킬 수 있다.** 비밀번호가 설정되지 않은 환경에서는 관리자 영역이 열리지 않는다.
  설정을 깜빡해서 무인증으로 열리는 사고가 구조적으로 불가능하다.
- `STAFF` 를 지금 만들면 쓰이지 않는 분기가 남는다. 견적 조회·상태 변경을 구현할 때 함께 넣는다.

## 하지 않기로 한 것

- **사용자 테이블과 비밀번호 해시.** 계정이 하나뿐인데 사용자 관리 화면까지 따라붙는다.
  개인별 추적이 필요해지는 시점이 Q-3 확정 시점이므로 그때 함께 만든다.
- **JWT 라이브러리 도입.** 서명·검증이 각각 몇 줄이라 의존성을 늘릴 이유가 없다.
- **`middleware.ts` 만으로 보호하기.** 레이아웃·미들웨어 검사에 의존하지 않는다는
  `.claude/rules/admin.md` 규칙에 따라 **API Route 안에서 다시 확인**한다.
  미들웨어는 화면 진입을 막는 1차 방어일 뿐이다.

## 영향

- `.env` 에 `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET` 이 필요하다. 없으면 `/admin` 은 404 처럼 닫힌다.
- 감사 로그로 "누가" 를 구분할 수 없다. 이 한계를 `docs/requirements.md` 8절 Q-3 에 남긴다.
- 비밀번호가 유출되면 가격 규칙 전체가 노출된다. 운영 배포 전 Q-3 확정이 필요하다.
