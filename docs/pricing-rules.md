# 가격 계산 업무 규칙

> 이 문서는 **업무 규칙(무엇이 맞는 금액인가)**을 정의한다. 코드 작성 규약은 `.claude/rules/pricing.md`를 본다.
> 취급 상품과 옵션 목록은 `docs/requirements.md` 3절이 기준이다.

## 1. 금액 단위

- 통화: 원(KRW) 단일.
- 모든 금액은 **원 단위 정수**로 저장·전달한다. 소수 원은 존재하지 않는다.
- **저장·계산되는 모든 금액은 현금가다.** 옵션 금액, 할인액, 소계, 총액 모두 현금가다. (ADR-0039)
  **카드로 결제하면 거기에 부가세 10%가 더해진다.** 7절을 본다.
- 할인율은 비율값으로 저장한다. 예: 15% → `0.1500`

## 2. 수량이 없다

이 서비스는 **수량 개념이 없다.** (ADR-0008)

컨설팅 상품은 "몇 개"를 사는 것이 아니라 "어떤 항목을 받을 것인가"를 고르는 것이다.
회차(3회차/6회차)나 자료 건수(5건/10건)도 수량이 아니라 **옵션 선택**이다.
3회차와 6회차의 금액 관계는 비례하지 않고 각각 정액으로 정해진다.

따라서 단가 × 수량, 수량 구간 단가, 최소·최대 수량이 모두 존재하지 않는다.
금액은 **선택한 옵션의 금액 합**으로만 만들어진다.

## 3. 계산 순서

순서를 바꾸면 결과가 달라진다. 아래 순서를 고정한다.

```
1. 옵션 금액 합  = 선택한 옵션들의 금액 합계
2. 항목 소계     = 1 → 10원 단위 버림
3. 견적 소계     = 모든 항목 소계의 합 (현재는 상품 1종이므로 항목 소계와 같다)
4. 할인액        = 견적 소계에 할인 규칙 적용 → 10원 단위 버림
5. 총액          = 3 - 4
```

- 이 순서에 부가세를 더하는 단계는 없다. 5번 총액이 **현금가**다. (ADR-0039)
  카드 결제 금액은 이 순서 밖에서 총액으로부터 구하는 표기값이다. 7절을 본다.
- 반올림은 **2번(항목 소계)**과 **4번(할인액)**에서만 수행한다. 중간 계산은 반올림하지 않는다.
- 반올림 방식: **10원 단위 버림**. 예: 5,065 → 5,060 / 101,309 → 101,300 (ADR-0007)
- 2번과 4번이 모두 10원 단위이므로 총액도 항상 10원 단위다.
- **선택이 없으면 소계 0, 할인 0, 총액 0이다.** 이것은 정상 결과다. 계산 거부가 아니다.

## 4. 옵션 금액

- 옵션은 **정액(원)** 으로만 금액에 영향을 준다. 정률 가산 옵션은 없다.
  수량도 기본가도 없으므로 비율을 곱할 기준값이 존재하지 않는다. (ADR-0008)
- 금액에 영향이 없는 옵션이 필요하면 금액 0으로 둔다. 별도 타입을 만들지 않는다.
- 옵션 금액은 전부 DB 값이다. 코드에 금액을 쓰지 않는다.

## 5. 옵션 선택 제약

| 제약 | 의미 | 위반 시 |
| ---- | ---- | ---- |
| 단일 선택 그룹 | 그룹 내 1개만 선택 가능 | 계산 거부 |
| 필수 그룹 | 해당 그룹에서 최소 1개 선택 | 계산 거부 |
| 선행 그룹 | 선행 그룹이 비었는데 이 그룹을 선택 | 계산 거부 |
| 선행 옵션 | 선행 그룹에서 지정된 옵션을 고르지 않고 이 그룹을 선택 | 계산 거부 |
| 미등록 옵션 | 이 상품에 없는 옵션 식별자 | 계산 거부 |

- 계산 거부는 금액 0원이 아니다. 금액을 내지 않고 **위반된 제약 목록**을 반환한다.
- 현재 상품 중 **필수 그룹은 없다.** 아무것도 선택하지 않은 0원 상태가 정상이기 때문이다.
  (`docs/requirements.md` F-1-8) 필수 그룹 검증 자체는 남겨 둔다. 나중에 지정할 수 있다.
- 배타 옵션 제약은 **없다.** 필요한 상품이 없어서 모델에 두지 않았다.
  다시 필요해지면 ADR을 남기고 추가한다.

### 5-1. 선행 그룹 (ADR-0010)

그룹이 다른 그룹을 선행 조건으로 가질 수 있다. 선행 그룹에 선택이 하나도 없으면
그 그룹의 옵션을 선택할 수 없다.

| 상품 | 그룹 | 선행 그룹 |
| ---- | ---- | ---- |
| 과정 컨설팅 | 소통 방식 | 회차 |
| 과정 컨설팅 | 수행평가 자료 요청 | 회차 |
| 과정 컨설팅 | 추가 옵션 | 회차 |

- 회차는 **필수가 아니다.** 아무것도 고르지 않은 상태는 위반이 아니라 0원이다.
  회차 없이 소통 방식만 고르는 것이 위반이다.
- 화면은 선행이 충족되지 않은 그룹을 비활성으로 두고, 선행 선택이 풀리면 딸린 선택도 지운다.
  서버 검증은 그와 별개로 항상 수행한다. (ADR-0003)

### 5-2. 선행 옵션 (ADR-0044)

선행 그룹을 **그 그룹의 특정 옵션 하나**로 좁힐 수 있다. 그 옵션을 고르지 않으면
같은 그룹의 다른 옵션을 몇 개 골랐든 충족되지 않는다.

| 상품 | 그룹 | 선행 그룹 | 선행 옵션 |
| ---- | ---- | ---- | ---- |
| 고2 올스토리 | 경쟁률 분석 | 단계 | 6단계 |
| 고3 올스토리 | 경쟁률 분석 | 단계 | 4단계 |

- 두 상품에서 그 단계가 수시 6장 최종 지원전략이다. 지원 대학을 정하는 상담 없이
  경쟁률을 분석할 대상이 없다.
- 선행 옵션이 지정되지 않은 그룹은 5-1 그대로다. 그룹에 선택이 있으면 충족이다.
- 선행 옵션이 비활성이거나 코드가 해석되지 않으면 그 그룹은 **선택할 수 없다.**
  조건을 무시해 파는 쪽이 아니라 팔지 않는 쪽으로 실패한다.

## 6. 할인

- 할인은 **견적 소계(3번)** 기준으로 적용한다.
- 할인 종류

| 종류 | 의미 |
| ---- | ---- |
| `RATE` | 소계의 n% 할인 |
| `FIXED` | 정액 n원 할인 |

### 6-1. 적용 조건

할인 규칙은 **조건 옵션 목록**을 가진다. 그 옵션을 **전부 선택했을 때** 자동으로 적용된다. (ADR-0009)

| 할인 | 상품 | 종류 | 조건 옵션 |
| ---- | ---- | ---- | ---- |
| 전단계 할인 | 고2 올스토리 | `FIXED` 45,000원 | 1 ~ 6단계 전부 |
| 전단계 할인 | 고3 올스토리 | `FIXED` 37,000원 | 1 ~ 4단계 전부 (= 고2 3 ~ 6단계) |

- 조건 옵션 외에 다른 옵션을 더 선택해도 할인은 유지된다. 조건은 "전부 포함"이지 "정확히 일치"가 아니다.
- **전단계 할인 둘 다 정액이다.** (ADR-0028, ADR-0030) 통합등록 금액은 단계 합에서 유도된
  값이 아니라 따로 정해진 값이고, 할인액은 그 금액을 맞추기 위한 차액이다.

  | 상품 | 단계 합 | 통합등록 | 할인액 | 비율로 두면 |
  | ---- | ---- | ---- | ---- | ---- |
  | 고2 올스토리 | 1,535,000 | 1,490,000 | 45,000 | 2.9316% → 총액 1,490,030 |
  | 고3 올스토리 | 1,187,000 | 1,150,000 | 37,000 | 3.1171% → 총액 1,150,090 |

  비율은 만분율 정수에 담기지 않아 통합등록 금액을 맞추지 못한다.
  **단계 금액을 바꾸면 할인액도 다시 계산해야 한다.** (단계 합 − 통합등록가)
- 조건 옵션 목록이 비어 있는 할인은 **항상 적용 대상**이다. (전체 할인 쿠폰 등)
- 조건과 할인율은 모두 관리자가 설정한다. 코드에 상품 코드나 할인율을 쓰지 않는다.
- **1회성 컨설팅에는 할인이 없다.** (ADR-0026) 내신과 생활기록부를 함께 받는 경우는
  할인 조건이 아니라 `내신 + 생활기록부 분석` 이라는 **별도 옵션**이고, 그 옵션의 정액이 곧 묶음 금액이다.
  묶음을 옵션으로 두면 고객이 고른 것과 받는 상담이 1:1로 맞고, 견적서에 그 이름이 한 줄로 남는다.
  구성 옵션을 따로 고른 고객에게는 더 싼 묶음이 있다고 **안내**한다. 금액을 깎지 않는다. (10절, ADR-0037)

### 6-2. 중복과 선택

- **중복 적용하지 않는다.** 적용 가능한 할인이 여러 개면 **할인액이 가장 큰 것 하나**만 적용한다. (ADR-0006)
- 할인액이 같다면 `priority` 값이 낮은 규칙을 적용한다. 같은 입력이 항상 같은 결과를 내야 한다.
- 할인액은 견적 소계를 초과할 수 없다. 초과분은 소계까지로 자른다. (총액 최소 0원)
- 어떤 할인 규칙이 적용되었는지 결과에 함께 기록한다. 적용되지 않은 후보도 비교 근거로 남긴다.

## 7. 현금가와 카드 결제 금액 (ADR-0039)

- 3절 계산 순서가 만드는 총액은 **현금가**다. 화면과 견적서의 큰 숫자는 이 금액 하나이고,
  금액 옆에 `현금가`를 명시한다.
- **카드로 결제하면 현금가에 부가세 10%가 더해진다.** 세율 10% 기준.

```
카드 결제 금액 = floor((현금가 × 1.1) / 10) × 10
```

- 10원 단위 버림을 쓴다. 총액이 항상 10원 단위인데(ADR-0007) 1.1 을 곱하면 그 단위가
  깨진다. 버림이라 고객이 더 내는 쪽으로는 틀리지 않는다.

```
현금가 267,000 → 293,700   (버림이 일어나지 않는다)
현금가     210 →     230   (231 → 230)
현금가  59,990 →  65,980   (65,989 → 65,980)
현금가       0 →       0
```
- 이 금액은 **저장하지 않는다.** 현금가에서 언제든 다시 구한다.
- 적는 자리는 **결제 방식을 고르는 곳 하나**다. 요약·견적서의 큰 숫자로 올리지 않는다.
- **공급가액·세액 분리 표기는 없다.** 현금가가 기준 금액이므로 `현금가 ÷ 1.1` 은 어떤
  거래에도 등장하지 않는 숫자다. 세금계산서가 필요한 건은 카드 금액을 기준으로 끊고,
  그 계산은 회계에서 한다.
- 면세 품목은 없다고 전제한다. 생기면 ADR-0039를 재검토한다.

## 8. 적용 시점

- 모든 가격 규칙은 `effectiveFrom`(적용 시작 일시)을 가진다.
- 계산에는 **계산 시점에 유효한 가장 최근 버전**을 사용한다.
- 미래 날짜로 등록된 규칙은 그 시점이 되기 전까지 계산에 쓰이지 않는다.
- 저장된 견적은 계산 당시 사용한 규칙 버전을 스냅샷으로 보존한다. 규칙이 바뀌어도 과거 견적 금액은 변하지 않는다.
- 할인 조건은 옵션 **코드**로 등록하고, 조회 시점에 유효한 옵션 버전으로 해석한다.
  금액만 바꾼 새 버전을 등록해도 조건이 깨지지 않는다. (`docs/requirements.md` Q-8)

## 9. 계산 예시 (회귀 테스트 기준값)

아래 금액은 `prisma/seed.ts`의 값이다. **네 상품 모두 확정값이고 임시값은 없다.**
(ADR-0026, ADR-0027, ADR-0028, ADR-0029, ADR-0030)
금액이 바뀌면 이 절과 테스트를 함께 갱신한다.

### 9-1. 1회성 컨설팅 — 분석 항목 3개 선택

```
내신 성적 분석 (30분)              =    59,000
모의고사 성적 분석 (30분)          =    59,000
생활기록부 분석 (1시간)            =   149,000
항목 소계                          =   267,000
견적 소계                          =   267,000
할인 없음                          =         0
총액                               =   267,000   (현금가)

(결제 방식 선택 자리에만 적는 표기값)
카드 결제 금액 = floor(267,000 × 1.1) = 293,700
```

1회성 컨설팅에는 할인 규칙이 없다. 몇 개를 고르든 소계가 그대로 총액이다.

### 9-2. 1회성 컨설팅 — 묶음 옵션 한 개 선택

```
내신 + 생활기록부 분석 (60~70분)   =   199,000
소계                               =   199,000
총액                               =   199,000
```

같은 상담을 따로 고르면 59,000 + 149,000 = 208,000 이다. 묶음 옵션이 9,000원 싸고,
그 차액은 할인 규칙이 아니라 묶음 옵션의 정액 자체에 들어 있다. (ADR-0026)
따로 고른 선택(총액 208,000)에는 **묶음 안내**가 붙는다. 총액은 208,000 그대로다. (10절, ADR-0037)

### 9-3. 과정 컨설팅 — 6회차 + 카톡 + 10건

```
6회차 (1회당 60~80분)       = 1,100,000
카톡 소통 (6개월)           =   390,000
수행평가 자료 10건          =   450,000
소계                        = 1,940,000
할인 없음
총액                        = 1,940,000
```

### 9-3-1. 과정 컨설팅 — 3회차 + 추가 옵션

```
3회차 (1회당 60~80분)       =   580,000
모의고사 성적 분석 (30분)   =    59,000
소계                        =   639,000
총액                        =   639,000
```

추가 옵션은 회차를 고른 뒤에만 고를 수 있고 **여러 개 고를 수 있다.** (ADR-0027)
회차 선택을 풀면 추가 옵션 선택도 함께 지워진다. (ADR-0010)

### 9-4. 고2 올스토리 — 전단계 (통합등록)

```
1단계 (60~80분)                =   199,000
2단계 (60~80분, 첨삭 제외)     =   249,000
3단계 (60~80분)                =   199,000
4단계 (60~80분)                =   149,000
5단계 (60~80분)                =   249,000
6단계 (60~80분)                =   490,000
소계                           = 1,535,000
전단계 할인 (정액)             =    45,000
총액                           = 1,490,000
```

옵션 이름은 단계 번호와 괄호 한정까지다. 상담 제목(`고2 생기부 방향성 컨설팅` 등)은
한 줄 설명이라 금액표와 견적서에 나오지 않는다. (ADR-0031)

총액이 곧 **통합등록 금액**이다. 할인액은 이 금액을 맞추기 위한 값이다. (ADR-0028)

1~5단계만 선택하면 1,045,000이고 할인은 걸리지 않는다.
단계마다 금액이 다르므로 어느 단계를 빼는지에 따라 소계가 달라진다.

### 9-4-1. 고3 올스토리 — 전단계 (통합등록)

고3 1~4단계는 **고2의 3~6단계와 같은 상담**이다. 번호만 상품 안에서 다시 붙는다. (ADR-0029)

```
1단계 (60~80분)                =   199,000
2단계 (60~80분)                =   149,000
3단계 (60~80분)                =   249,000
4단계 (60~80분)                =   590,000
소계                           = 1,187,000
전단계 할인 (정액)             =    37,000
총액                           = 1,150,000
```

**4단계 590,000원은 같은 상담인 고2 6단계 490,000원과 금액이 다르다.** (ADR-0030)
같은 상담이어도 금액은 상품마다 따로 정해진다. 공유하는 것은 문구뿐이다.
이름이 번호와 소요 시간만 담으므로 두 상품의 같은 상담은 **이름으로 구별되지 않는다.**
어느 상담인지는 상품 탭과 한 줄 설명이 말한다. (ADR-0031)

1~3단계만 선택하면 597,000이고 할인은 걸리지 않는다.

### 9-5. 선택 없음

```
소계 0 / 할인 0 / 총액 0
```

위반 목록은 비어 있다. 0원은 정상 결과다.

### 9-6. 10원 단위 버림

현재 임시 금액표는 전부 1,000원 단위이고 할인율도 정수 퍼센트라서 **버림이 실제로 발생하지 않는다.**
버림 동작은 픽스처(예: 소계 33,773에 15% → 5,065.95 → 5,065 → 5,060)로 검증한다.
실제 금액표가 확정되어 버림이 발생하게 되면 이 절에 사례를 추가한다.

이 값은 `.claude/rules/testing.md`에 따라 단위 테스트로 고정한다.
구현: `src/services/pricing/calculate.test.ts`

## 10. 묶음 안내 (ADR-0037)

묶음 옵션은 구성 옵션들을 한 번에 받는 상담이고, 금액은 **그 옵션 자신의 정액**이다. (ADR-0026)
구성 옵션을 따로 고르면 합계가 묶음보다 비쌀 수 있다.

| 상품 | 묶음 | 구성 | 따로 고른 합 | 묶음 금액 | 차이 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| 1회성 컨설팅 | 내신 + 생활기록부 분석 (60~70분) | 내신 성적 분석 + 생활기록부 분석 | 208,000 | 199,000 | 9,000 |

이때 **더 싼 묶음이 있다고 안내한다.** 안내는 금액이 아니라 표시다.

- **총액에 들어가지 않는다.** 고객이 고른 옵션의 합이 그대로 총액이다. 3절의 계산 순서에
  단계가 추가되지 않는다.
- **할인이 아니다.** 1회성 컨설팅에 할인 규칙은 여전히 없다. (6-1)
- 안내 조건은 **구성 옵션 전부 선택 + 묶음 옵션 미선택**이다. 구성 외에 다른 옵션을 더
  골라도 안내는 유지된다. 조건은 "전부 포함" 이지 "정확히 일치" 가 아니다. (6-1과 같은 선)
- **절약액은 총액의 차이다.** `지금 총액 − 바꾼 뒤 총액` 이고, 구성 옵션 금액의 차를 따로
  빼지 않는다. 버림(2·4번)과 할인까지 포함해야 화면에 적는 "얼마가 줄어든다" 가 사실이 된다.
- 절약액이 **양수가 아니면 안내하지 않는다.** 묶음이 더 비싸거나 같으면 안내할 내용이 없다.
  구성 옵션을 빼면서 할인을 잃는 경우도 여기서 걸린다.
- 바꾼 선택이 **제약(5절)을 위반하면 안내하지 않는다.**
- 안내가 여러 건이면 절약액이 큰 순, 동률이면 옵션 식별자 순이다. 같은 입력이 같은 순서를 낸다.

바꾸는 것은 고객이 버튼을 눌렀을 때뿐이다. 자동으로 치환하지 않고, 저장 시점에도 바꾸지 않는다.
묶음은 소요 시간이 다른 별개 상담이고, 따로 받기를 택한 고객이 있을 수 있다.

어느 조합을 묶음으로 두는지는 **관리자 화면에서 추가·삭제한다.** (ADR-0038) 관계는 금액이
아니므로 적용 시작일이 없고, 저장 시점에 묶음이 더 싼지도 검증하지 않는다. 안내 여부는
위 조건대로 **그때그때의 두 총액 차이**가 정한다.
